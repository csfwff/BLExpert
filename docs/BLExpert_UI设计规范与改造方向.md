# BLExpert UI 设计规范与改造方向

## 文档状态

- 状态：建议立项
- 优先级：P0 信息架构与主工作流；P1 视觉令牌与组件规范；P2 高级效率功能
- 适用范围：BLExpert 桌面优先、兼容窄屏的跨平台 BLE 调试工作台
- 设计目标：从“多页配置界面”调整为“面向连续收发任务的专业工具界面”

## 结论

当前界面功能覆盖较多，但整体偏重，不够像高频使用的调试工具。核心问题不在于单一控件样式，而在于信息架构：通信控制台、工作区设置、协议配置、指令库、数据映射、特征操作和快捷指令被同时放在主工作台的同一层级；桌面端又采用主区与固定 390px 侧栏的双重 Tab 结构。

这会带来三个结果：

- 用户打开应用后，需要先理解多组 Tab 和顶部全局操作，才能完成“选设备、连接、选特征、收发数据”的基础任务。
- 高频运行态操作和低频配置态操作争夺同一首屏空间，控制台不再是稳定、连续的工作中心。
- 视觉表面和分组边界过多，界面容易呈现“配置页拼接”而非“工程调试台”。

后续 UI 应坚持以下定位：**BLExpert 是工程师连续使用的设备协议调试台，首屏应服务于连接、观测、发送和定位问题；工作区、协议、指令和映射是可进入的配置工作区，不应与实时通信争夺注意力。**

## 当前界面评估

### 已有基础

- 已具备亮色、暗色和跟随系统主题。
- 顶部已集中工作区、设备、连接和扫描操作。
- 实时收发控制台、特征操作、快捷指令和解析数据均已有明确能力入口。
- 组件圆角总体较小，未使用明显营销化的大卡片设计。
- 宽屏与窄屏已有基础响应式分支。

### 主要问题

#### P0：运行态与配置态混杂

主工作区 Tab 同时承载“通信”“工作区设置”“协议配置”“指令库”“数据映射”；设备侧栏又包含“特征”“快捷指令”“数据视图”。这等于把两种不同心智任务放在同一层：

- 运行态：扫描、连接、选择特征、订阅、收发、查看日志和数据。
- 配置态：维护工作区、命令、协议、脚本、映射和导入导出。

建议：将运行态固定为默认工作台，将配置态迁移为独立的工作区编辑器或右侧可关闭 Inspector，不再作为主区域的常驻 Tab。

#### P0：双层 Tab 导航成本过高

宽屏下用户需要理解左侧 5 个主 Tab 和右侧 3 个侧栏 Tab。两套 Tab 都在页面顶部附近，层级不够明确，且切换一个区域会使另一块区域仍占据大量视觉空间。

建议：主导航只保留一套。设备特征、快捷命令和数据状态应由右侧 Inspector 的分段视图、可折叠区或上下文面板承载；配置能力进入独立“配置”视图。

#### P0：顶部工具栏承担了过多不同频率操作

当前顶部同时展示工作区选择、设备选择、连接、扫描、Web UUID、导出预览、主题和语言。连接操作与全局偏好、开发辅助和导出操作的优先级不一致，降低了设备状态的可读性。

建议：顶部仅保留品牌、工作区、设备连接状态、扫描/连接主操作及溢出菜单。主题、语言、Web UUID、导入导出和开发诊断进入菜单或配置视图。

#### P1：工具面板存在重复标题和重复容器

多个 Tab 页面在 Tab 标题之后再次呈现同名标题，例如“特征”“快捷指令”“数据视图”。大量 `Container`、分隔线、局部背景和边框使界面分区多于真正的任务分区。

建议：页面标题只出现一次；运行态通过 1px 分隔线、密度和区域标题区分层级，避免每个区域再套一层视觉容器。

#### P1：控制台的调试密度仍偏低

控制台是主要工作区，但顶部操作区、底部输入区和日志行的结构还没有形成典型协议分析工具的高密度可扫描样式。输入区中的文本模式、HEX 模式、行尾规则和发送操作也缺少清晰的“编辑器工具条”关系。

建议：日志行按方向、时间、特征、长度、HEX、ASCII/解析结果建立固定列或稳定字段顺序；输入区采用单行/可展开编辑器和紧凑工具条；发送按钮始终位于编辑器右侧并保持固定尺寸。

#### P1：窄屏布局依赖固定高度堆叠

窄屏模式通过固定高度的工作台和侧栏上下堆叠，容易造成内容截断、滚动层嵌套和当前连接状态不易获取。

建议：窄屏采用底部导航或单一页面栈，在“调试”“设备”“配置”之间切换；连接状态和发送入口保持常驻或可快速回到。

## 用户与核心任务

主要用户是嵌入式、IoT、测试和现场支持工程师。设计应优先保障以下连续任务：

1. 选择工作区，扫描并连接目标设备。
2. 查看连接、服务和特征状态，选定写入和订阅目标。
3. 订阅通知后持续观测原始数据、协议解析状态和关键字段。
4. 快速编辑并发送一帧数据，或执行已配置命令。
5. 在异常发生时定位时间、方向、特征、原始数据、解析结果和错误。
6. 在非实时调试时维护命令、协议、脚本、映射和工作区配置。

界面不得要求用户在每一步都离开控制台，也不应把低频配置入口常驻展示在高频收发视图中。

## 目标信息架构

### 顶层结构

建议采用三个明确的工作模式，而不是两套并列 Tab：

| 模式 | 用途 | 默认可见内容 |
| --- | --- | --- |
| 调试 | 日常连接、收发、订阅、观察和问题定位 | 设备上下文、通信控制台、右侧 Inspector |
| 配置 | 维护工作区、协议、命令、映射和脚本 | 左侧配置导航、主编辑器、校验/预览区域 |
| 记录 | 查阅、筛选、导出会话日志和解析结果 | 日志列表、筛选器、详情面板 |

桌面端可以使用窄 `NavigationRail` 或左侧图标导航切换三种模式；窄屏采用底部导航。默认打开“调试”。

### 调试模式布局

推荐三栏结构，优先保持控制台稳定：

```text
[工作区/设备上下文栏 240px] [通信控制台，自适应主区] [Inspector 320px，可收起]

左栏：设备列表、扫描、连接状态、服务/特征树
主区：会话状态条、过滤工具条、通信日志、发送编辑器
右栏：当前特征、订阅/写入目标、快捷命令、最新解析数据
```

- 左栏只服务“选择对象”：工作区、设备、服务、特征。
- 主区只服务“观察与发送”：日志始终居中、最大化且不随配置页面消失。
- 右栏只服务“当前对象的上下文操作”：默认展示当前特征；无选中对象时展示连接引导。
- Inspector 可关闭，关闭后控制台占满主区；用户偏好应被记住。

### 配置模式布局

```text
[配置导航 220px] [编辑器主区] [校验/预览 Inspector 300px]

配置导航：工作区、设备连接、命令、标准协议、脚本协议、响应映射、安全状态、导入导出
编辑器：列表 + 详情编辑，或单项编辑器
Inspector：模型校验、JSON 预览、依赖关系、风险提示、保存状态
```

- 协议和脚本仍属于同一个“协议”配置节点，使用局部模式切换。
- 命令、映射和特征默认配置应采用主从式列表编辑，避免把列表管理放进运行态 Tab。
- 导入导出、Web 服务 UUID、主题和语言不进入主调试工具条。

### 记录模式布局

- 用于历史会话回放、方向/特征/命令筛选、错误定位与导出。
- 实时控制台只显示当前会话；长期记录、导出和筛选在此模式完成。
- 数据映射展示应以“最新值 + 变更时间 + 来源帧”构成可追溯关系，不能只有计数卡和最近日志副本。

## 视觉设计规范

### 设计气质

- 安静、直接、紧凑、可长时间使用。
- 视觉重点使用在连接状态、错误、数据方向、当前选中对象和危险操作上。
- 禁止营销式英雄区、大尺寸装饰标题、渐变背景、装饰性卡片堆叠和无意义色块。
- 保持中文优先，但 UUID、HEX、脚本、命令码和时间戳采用等宽字体。

### 颜色与状态

采用语义颜色，而不是将同一蓝色用于所有强调：

| 语义 | 建议表现 | 使用范围 |
| --- | --- | --- |
| 中性 | 低对比背景、1px 分割线 | 页面分区、未选中项 |
| 选择/主操作 | 单一主色 | 当前选中对象、连接、发送 |
| 接收数据 | 青绿或冷色辅助色 | RX 方向标记、接收摘要 |
| 发送数据 | 蓝色或中性色强调 | TX 方向标记、发送摘要 |
| 警告 | 琥珀色 | 未订阅、脚本未信任、配置不完整 |
| 错误/危险 | 红色 | 连接错误、解析错误、破坏性命令 |
| 成功 | 绿色 | 已连接、订阅已启用、校验通过 |

- 色彩不能作为唯一信息来源；所有状态同时提供图标、短标签或文本。
- 暗色主题使用中性深灰层级，避免大面积纯黑和高饱和蓝色覆盖整个界面。
- 状态色只用于局部标识，不用于整块页面背景。

### 排版与数据格式

- UI 正文统一使用系统无衬线字体；HEX、UUID、命令码、长度、时间和脚本使用等宽字体。
- 不使用随视口变化的字体大小；标题层级固定、克制。
- 主要标题 18-20px，区域标题 14-16px，正文 13-14px，元数据 11-12px。
- 字母间距保持默认，不使用负字距。
- UUID 在窄空间必须尾部省略，但支持复制和悬停查看完整值。
- HEX 显示固定为大写、空格分组；一行过长时换行规则稳定，不能挤压操作按钮。

### 尺寸与密度令牌

建议将以下数值提取为统一主题扩展或共享常量：

| 令牌 | 建议值 |
| --- | --- |
| 页面外边距 | 12px 桌面，8px 窄屏 |
| 控件高度 | 32px 紧凑，40px 常规 |
| 图标按钮 | 32x32px 紧凑，40x40px 触控优先场景 |
| 区域间距 | 8px / 12px / 16px 三档 |
| 输入框内部边距 | 8px 水平，6px 垂直 |
| 圆角 | 4px 一般表面，6px 弹窗和独立工具；避免更大圆角 |
| 分割线 | 1px，低对比但清晰可见 |
| 左栏宽度 | 220-260px，可拖拽或折叠 |
| Inspector 宽度 | 300-360px，可拖拽或折叠 |

### 表面与容器

- 页面区域不使用浮动卡片；采用连续画布、区域标题和分割线。
- 卡片仅用于命令项、临时提示、模态对话框和真正独立的工具单元。
- 禁止卡片嵌套卡片。
- 固定工具条和输入区应使用底边/顶边分隔，不依赖阴影表达层级。
- 所有可滚动区域必须只有一个明确的主滚动容器，避免 Tab 内层层滚动。

### 按钮、图标与输入

- 图标按钮用于扫描、连接、清空、复制、过滤、导出、设置等熟悉操作，必须提供 tooltip。
- 文本按钮只用于清晰命令，如“发送”“保存”“导入”“新建命令”。
- 不为主题、语言、导出预览等低频操作占用首层工具条；使用溢出菜单。
- 二元开关使用 `Switch` 或复选框，不用文本按钮模拟状态。
- 模式切换使用紧凑分段控件，例如 HEX / 文本、标准协议 / 脚本协议。
- 数值参数使用对应输入约束、步进器或下拉列表；枚举不可退化为自由文本。

## 关键组件规范

### 应用顶部栏

应包含：

- BLExpert 名称或简洁品牌标识。
- 当前工作区名称及修改状态。
- 当前设备名称、连接状态和连接主操作。
- 扫描操作。
- 溢出菜单。

应移入溢出菜单或配置模式：主题、语言、Web UUID、导入导出、开发诊断、关于。

连接状态建议以紧凑状态胶囊展示：`未连接`、`连接中`、`已连接`、`错误`。状态胶囊是信息展示，不应替代明确的连接/断开按钮。

### 设备与特征树

- 使用树状列表展示服务和特征，不以一组组卡片呈现。
- 每个特征行固定展示：名称/UUID、属性标签（R/W/NR/N/I）、当前选择状态和行内操作。
- 行内操作应为 Read、设为写入、订阅/取消订阅，图标加 tooltip；复杂选项通过上下文菜单展开。
- 仅在已连接后显示可操作状态；断开时保留上次结构的弱化视图或提供明确空状态。

### 通信控制台

日志列表是主工作区，最低应包含：

| 字段 | 说明 |
| --- | --- |
| 时间 | 固定宽度，可精确到毫秒 |
| 方向 | TX、RX、SYS、ERR，配合图标与语义色 |
| 来源 | 特征短 UUID 或命令名 |
| 长度 | 字节数 |
| 原始数据 | HEX，等宽显示 |
| 解析摘要 | 可选，解析成功或错误摘要 |

- 工具条至少包含方向筛选、特征筛选、文本/HEX 查找、自动滚动、清空和导出。
- 点击一行在 Inspector 展开完整帧、ASCII、解析结果、脚本日志和复制动作。
- 控制台应始终保留原始帧；解析结果是附加信息，不得替代原始数据。
- 将当前无边界的日志缓存改为有限环形缓冲，默认上限需可配置。

### 发送编辑器

- 默认是一行等宽 HEX 编辑器，可展开为多行。
- HEX / 文本 / ASCII 与行尾规则形成同一紧凑工具条。
- 发送按钮固定靠右，连接未建立或未选择写入特征时禁用并解释原因。
- 显示当前写入特征的短 UUID；点击可跳转或重新选择特征。
- 脚本模式下展示“业务载荷 -> 最终帧”预览；涉及危险命令时要求确认。

### 快捷命令

- 在调试模式右侧 Inspector 中按分组显示，不应独占主要页面 Tab。
- 单条命令是紧凑行或低圆角工具项：名称、载荷摘要、参数输入和发送图标。
- 参数较多的命令在点击后展开，避免所有参数输入常驻占据列表。
- 发送成功后可在控制台中定位相应 TX 记录。

### 数据 Inspector

- 默认展示最新解析响应，不展示仅供装饰的统计卡片。
- 每项字段应包含：名称、当前值、单位、更新时间、来源命令或帧。
- 数据异常、校验失败和陈旧值应有明确状态。
- 图表功能上线前，避免用大量空白或占位卡片填充数据页。

### 配置编辑器

- 采用左侧配置目录 + 主编辑器，不使用运行态控制台的 Tab 容器。
- 所有编辑器应提供保存状态、验证错误、撤销/重做和未保存离开提醒。
- 协议配置显示发送帧、接收帧和字段范围的可视化预览；脚本配置显示运行状态和安全信任状态。
- 导入工作区中的脚本必须显示“未信任、已禁用”状态，直到用户明确确认。

## 响应式规范

### 宽屏：大于等于 1200px

- 三栏调试布局。
- Inspector 默认打开，允许用户关闭或调整宽度。
- 设备树、控制台、Inspector 各自独立滚动，禁止整体页面滚动替代控制台滚动。

### 中等宽度：768px 至 1199px

- 两栏布局：控制台主区 + 可抽屉化 Inspector。
- 设备树可折叠为左侧抽屉或上方对象选择条。
- 配置模式仍为左侧导航 + 主编辑器，但 Inspector 默认收起。

### 窄屏：小于 768px

- 使用“调试 / 设备 / 配置”底部导航或等价单层页面导航。
- 不使用固定高度 620px / 560px 的上下堆叠面板。
- 连接状态、当前设备和发送入口保持快速可达。
- 表格化日志转为两行列表：首行时间、方向、来源、长度；次行 HEX 摘要。详情在点击后打开底部面板。

## 推荐改造路线

### 第一阶段：降低运行态复杂度

目标：不改业务模型，先让首屏回归调试台。

1. 将顶部的主题、语言、导出预览、Web UUID 移入溢出菜单。
2. 将工作区设置、协议配置、命令库和数据映射从主工作台 Tab 迁入独立“配置”视图。
3. 调试视图默认只展示设备树、控制台和 Inspector。
4. 合并右侧“特征 / 快捷指令 / 数据视图”三套 Tab 为 Inspector 分区或上下文分段控件。
5. 移除重复标题、重复背景容器和不必要的边框；统一为分割线分区。
6. 为 Inspector 和左栏增加折叠状态并持久化用户偏好。

验收：用户在首次进入后，无需切换 Tab 即可完成扫描、连接、选特征、订阅、发送和查看 RX/TX。

### 第二阶段：重构控制台与发送效率

目标：使控制台成为可靠的协议观测中心。

1. 建立结构化日志行模型，补充来源特征、长度、方向、解析摘要和错误级别。
2. 增加方向、特征、关键字和错误筛选，以及单条详情 Inspector。
3. 改造发送编辑器为紧凑等宽编辑器 + 固定发送操作。
4. 补充复制 HEX、复制 ASCII、重发、收藏帧和定位关联命令等高频动作。
5. 实现有限日志缓存和会话导出。

验收：工程师可在一个连续视图内定位某条通信、查看完整上下文、复制/重发数据并看到结果。

### 第三阶段：配置工作区专业化

目标：让复杂模型可维护而不污染调试态。

1. 将 `lib/main.dart` 拆分为 shell、debug、configuration、record、device-tree、console、inspector 等模块。
2. 引入应用状态管理，区分全局 UI 状态、连接状态、工作区编辑状态与会话状态。
3. 为命令、协议、脚本和映射建立一致的列表-详情编辑模式。
4. 增加未保存状态、验证、预览、撤销和导入风险提示。
5. 脚本安全整改完成后，再把信任状态、执行预算和安全警告接入配置 UI。

验收：配置大型工作区时，用户不需要回到调试界面；回到调试界面时，连接和控制台上下文不丢失。

### 第四阶段：高级效率与可访问性

- 快捷键：扫描、连接、发送、清空、聚焦发送编辑器、切换自动滚动。
- 可保存的面板布局和日志筛选预设。
- 高对比度、键盘焦点、屏幕阅读器标签和最小触控目标测试。
- 会话书签、命令执行历史和响应帧关联。

## 实施约束

- 不在现有 `lib/main.dart` 中继续叠加新 UI；结构改造必须先拆分模块边界。
- 不以“换一套颜色、加阴影或加卡片”为改造目标，优先处理信息架构和任务流。
- 不因视觉改造破坏现有 BLE、脚本、工作区、命令和数据映射行为。
- 新 UI 必须在亮色、暗色、宽屏和窄屏下验证文本溢出、滚动行为、焦点顺序和操作可达性。
- 未完成脚本安全 P0 前，配置界面必须保留脚本风险与信任状态的展示位置。

## 关联现状

当前实现集中在 `lib/main.dart`：应用主题、顶部工具栏、主工作台 5 个 Tab、设备侧栏 3 个 Tab、控制台、发送编辑器、快捷命令和数据摘要均在同一文件中。改造时应先按页面与功能边界拆分，避免在单一入口文件中继续增加布局分支。
