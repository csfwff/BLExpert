# 产品说明

> 文档基线：2026-08-17。这里描述已交付的产品边界；进行中的事项以 [开发路线图](开发路线图.md) 为准。

## 定位

BLExpert 是面向嵌入式、IoT、测试和现场支持工程师的跨平台 BLE 协议调试与分析工具。它将设备连接、原始收发、协议规则、业务指令和字段映射收敛在可复用的工作区中，减少从协议文档到真实设备调试的重复配置。

产品是工程调试台，不是通用仪表盘或营销产品。首要任务是让用户可靠地连接设备、观察通信、发送数据和定位协议问题。

## 用户与场景

主要用户：

- 嵌入式固件开发人员。
- IoT 设备与移动端联调人员。
- 测试、验证和现场支持工程师。

典型任务：

1. 扫描并连接 BLE 设备。
2. 选择 GATT 服务、写入特征和通知/指示特征。
3. 持续查看 RX/TX、系统事件和错误。
4. 手动发送 HEX/文本，或执行带参数的业务指令。
5. 通过协议配置、脚本和字段映射理解设备响应。
6. 保存、导入或导出工作区，复用设备调试配置。

## 产品范围

### 支持范围

- BLE Central：扫描、连接、断开、GATT 服务与特征发现、读写、Notify、Indicate。
- 工作区：协议配置、脚本配置、指令、响应映射、设备默认连接配置和本地持久化。
- 调试：原始通信日志、手动发送、快捷指令、标准协议封包/解帧和结构化字段展示。
- 平台：Android、iOS、Windows、macOS、Linux 和 Web，具体能力受系统蓝牙栈与浏览器限制。

### 明确不支持

- 经典蓝牙 SPP/RFCOMM。
- BLE Peripheral/设备模拟模式。
- 在 Web 端执行 JavaScript 协议脚本。
- 将导入或 AI 生成脚本自动视为可信并执行。

## 核心领域模型

```text
Workspace
  ├── ProtocolDefinition：发送/接收帧片段、长度、序号和校验配置
  ├── ScriptConfig：发送前 / 接收后 JavaScript 协议处理
  ├── CommandDefinition：业务载荷、参数和快捷入口
  ├── ResponseMapping：CMD/DATA 到业务字段的映射
  └── DeviceProfile：设备元信息与调试备注
```

领域职责：

- 协议层处理帧头、帧尾、长度、序号和校验；标准协议已覆盖常见固定结构，转义、加密和复杂状态机由脚本或后续扩展承担。
- 指令层处理业务命令和参数，不直接管理协议字段。
- 映射层从稳定的 `CMD/DATA` 解析业务字段，偏移从 `DATA` 第 0 字节开始。
- 蓝牙服务层只负责 BLE GATT 连接与字节收发，不承担协议业务规则。

## 体验原则

- 默认进入调试工作台；控制台是运行态的视觉中心。
- 设备树用于选择服务与特征；Inspector 展示当前对象操作与状态。
- 协议、指令、映射和脚本属于独立配置工作流，不与实时收发争夺首屏。
- 原始 BLE 数据始终可见；协议、脚本或映射失败不能吞掉原始记录。
- 发送真实设备数据时，错误、风险和目标特征必须明确可见。
- 导入脚本默认禁用并标记未信任，必须经用户明确确认后才可启用。
- 亮色、暗色、宽屏和窄屏都应保持紧凑、可扫描和可访问。

完整 UI 规范见 [UI设计规范](UI设计规范.md)。

## 技术基础

- Flutter / Dart `^3.12.1`。
- BLE：`universal_ble`，Web 使用 `flutter_web_bluetooth` 与浏览器 GATT 能力。
- 脚本：原生使用 `flutter_js`；Web 仅保存配置，不执行脚本。
- 本地配置：`shared_preferences`。
- 质量门槛：`flutter analyze` 和 `flutter test`。
