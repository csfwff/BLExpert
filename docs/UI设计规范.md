## 设计定位

BLExpert 是面向嵌入式、IoT、测试和现场支持工程师的设备协议调试台。它不是仪表盘、营销页面或通用 CRUD 后台。

界面必须优先帮助用户持续完成以下任务：

1. 选择工作区与设备，完成扫描和连接。
2. 选择服务、特征、具体写入模式与订阅方式。
3. 连续观察 RX/TX、系统事件、错误和已解析字段。
4. 快速编辑并发送原始帧，或执行已配置命令。
5. 定位一条通信的来源、时间、长度、原始帧、解析结果与相关操作。
6. 在离开实时调试状态后维护协议、命令、映射、脚本和工作区。

**设计总原则：控制台是运行态中心；设备树用于选对象；Inspector 用于当前上下文操作；配置是独立工作流。**

## 重构验收：已完成内容

上一轮 UI 重构已完成核心架构调整，不应再作为待办重复实施。

### 已完成：顶层模式分离

当前已将应用拆为三个顶层模式：

| 模式 | 当前职责 | 入口 |
| --- | --- | --- |
| 调试 | 设备、特征、通信控制台、当前上下文 | 桌面 shadcn `NavigationRail` / 窄屏 shadcn `NavigationBar` |
| 配置 | 工作区、协议、指令、响应映射 | 独立配置导航 |
| 记录 | 有界会话日志、筛选、书签、导出与基础事务回溯 | 独立记录视图 |

这解决了旧版“运行态与配置态共用多层 Tab”的主要问题。桌面端已采用模式导航栏，窄屏端已采用底部导航，符合 Flutter 场景下通过 `LayoutBuilder` 根据约束切换布局的实践。

### 已完成：调试工作台三栏结构

调试模式现已形成明确边界：

```text
[模式导航] [设备与特征] [通信控制台] [当前上下文 Inspector，可收起]
```

- 左侧设备区承担设备、服务和特征选择。
- 中央控制台承担持续观测与发送。
- 右侧 Inspector 承担快捷命令、映射数据和当前上下文。
- Inspector 可关闭以放大通信控制台。

这是正确的工具型布局，应继续保留，后续不应回退为两套并列 Tab。

### 已完成：工具栏降噪

主题、语言、Web 服务 UUID 与工作区导入导出已进入溢出菜单；工作区导出明确区分当前工作区与全部工作区。应用栏保留工作区、设备、连接状态、扫描与连接等高频运行态操作，信息优先级已明显改善。

工作区导入在紧凑工具弹窗中先展示格式/脚本/冲突预览，再使用分段控件选择完整替换或合并导入；仅在合并且存在冲突时展示覆盖当前/保留当前，避免将不相关的策略暴露给普通导入流程。

### 已完成：发送与数据状态表达

- 调试发送区在同一工具带中展示 HEX/文本模式、行尾、发送状态、业务载荷字节数和最终帧；预览区域使用 `NotoSansSC` 文案与 `GeistMono` 帧数据，并保持固定布局，避免状态文案让输入框上下跳动。
- HEX 输入只接受 `0-9`、`A-F`，自动大写并按两个字符分组；不完整字节或其他非法内容直接进入校验错误态。
- 日期/时间类型参数在发送时解析当前时间；空的年、月、日、时、分、秒参数不应在日志中继续显示为空值。
- 高风险命令、显式保护命令和脚本改写帧均经过安全发送路径。脚本协议配置提供“脚本改帧发送前确认”开关，关闭后只跳过脚本改帧这一层确认，不改变其他强制确认规则。
- 响应映射字段发生变化后保持高亮，直到映射数据被清空；高亮同时使用背景、边框和语义信息表达，不能只依赖颜色。
- 发送禁用原因和业务载荷字节数位于发送区行尾右侧，并保留与滚动条的安全边距；文案使用界面字体，帧值使用等宽字体。

### 已完成：基础视觉令牌与响应式基础

- 使用低圆角、零卡片阴影、分隔线和中性表面层级。
- 工作台一般表面使用 4px 圆角，工具对话框使用 6px 圆角；不使用 shadcn 默认 XXL 大圆角，避免弹窗与高密度工具栏产生风格断裂。
- 应用栏、面板标题、控制台标题和对话框已使用一致的图标、层级和分隔线表达；列表项由独立圆角卡片收敛为连续工具列表。
- 亮色、暗色与系统主题均可用。
- 桌面 shadcn `NavigationRail`、窄屏 shadcn `NavigationBar`、调试三栏和配置双栏均通过 `LayoutBuilder` 适应宽度。
- 图标按钮已配置紧凑最小尺寸和 tooltip 主题。
- 已引入局部 `Semantics` 和多数图标按钮 tooltip。

### 令牌分层

后续调整按“基础值 -> 语义值 -> 组件值”理解和复用，不在业务页面继续散落近似数值。

| 层级 | 当前基线 | 使用规则 |
| --- | --- | --- |
| 界面字体 | `Noto Sans SC` | 中文、英文和数字共用项目内置字库，不依赖操作系统字体回退，保持 Windows、Web 和其他平台的字形与基线一致。 |
| 技术数据字体 | `Geist Mono` | HEX、UUID、协议帧、日志和实时数值统一使用；业务代码不得直接声明泛化的 `monospace`。 |
| 基础间距 | 2 / 4 / 6 / 8 / 12 / 16 / 20px | 页面和区域布局优先使用 4 / 8 / 12 / 16px；2 / 3 / 6px 只用于紧凑控件内部微调。 |
| 配置二级页面边距 | 16px | 工作区、协议、指令与响应映射页面使用同一页面边距；列表项和表单内部密度按各自组件规范处理。 |
| 紧凑文字 | `typography.xSmall`，当前 12px | 工具栏按钮、选择器值、紧凑输入和菜单项保持一致，不在同一工具带混用默认字号。 |
| 辅助技术文字 | 10px | 仅用于 UUID、日志方向徽标、能力标记等不可交互的辅助技术元数据；参数标签、输入占位符和操作命令保持 12px。 |
| 设置表单 | 单项横向行，标签宽 96px、间距 12px | 桌面设置页每行只放一个字段；窄于 560px 时标签移到输入框上方。只读统计不得伪装成可编辑配置项。 |
| 紧凑模式切换 | 高 32px、12px 文案、水平 10px | 用于协议模式等页面内视图切换；保持选中语义、图标与文字同步变色、键盘焦点和单行标签。控制项作为独立工具带紧邻其接管的内容区域。 |
| 协议帧片段列表 | 桌面端一项一行、行间 8px | 类型、名称、参数和行操作保持在同一横行；输入框与下拉框统一为 24px 高、12px 文字和紧凑内边距，下拉菜单项高 28px。动态项使用稳定 key；新增片段操作放在列表末尾，选择菜单锚定在按钮附近。窄屏空间不足时自适应为纵向字段。 |
| 工具栏控件 | 高 36px、相邻间距 8px | 同层级选择器和命令按钮保持同高；成组且文案长度相近时优先等宽。 |
| 紧凑输入 | 水平 6px、垂直 4px | 带图标输入使用项目适配层的专用密度，不直接沿用第三方默认大内边距。 |
| 紧凑弹层项 | 高 24px、水平 4px、垂直 2px | 用于桌面设备选择等高频短列表；保持焦点、键盘选择、勾选和关闭行为。 |
| 工具弹窗 | 内容宽度约 520px、6px 圆角 | 复杂但短小的设备/安全配置；内容过长时只滚动内容区。 |
| 弹窗操作 | 高 34px、水平 20px、垂直 4px | 底部取消与确认按钮同高，按钮整体呈横向，避免过厚。 |
| 图标 | 工具栏 18px、弹窗标题 19px | 同一层级使用一致的 Lucide 线性图标与尺寸。 |

上述值是当前组件语义，不要求所有控件一律使用 36px 或 136px。例如记录筛选可使用 32px 紧凑高度，普通表单可使用 40px；但同一行、同一层级的控件不得无理由混用高度、字号和内边距。

### 首页工具栏标准

桌面宽度充足时，工作区选择、设备选择、连接/断开和扫描组成一个连续工具组：

| 属性 | 标准 |
| --- | --- |
| 单个控件外框 | 136 x 36px |
| 控件间距 | 8px |
| 文案 | 12px，单行；动态值过长省略，固定动作文案不得改变整组字号 |
| 图标 | 18px，图标与文案垂直居中 |
| 选择器内边距 | 水平 6px、垂直 3px |
| 工作区/设备选择 | 中性描边表面，内容左对齐，尾部提供展开指示 |
| 扫描/连接主操作 | 使用主操作色；连接中、断开中保持可辨识边界和稳定底色 |

执行规则：

- 同一工具组先统一高度、宽度、字号和间距，再处理各自图标与状态；不得通过某一个控件的默认主题决定整组尺寸。
- 工作区菜单和设备弹层在桌面端与触发器同宽，打开前后不能出现明显宽度或密度跳变。
- 设备弹层项使用 24px 紧凑行高、12px 文案和 4px 水平内边距。长设备名保持单行并省略，不能撑宽弹层。
- 工作区菜单包含管理命令时仍保持紧凑，但不得为了追求相同行高而删除分组、选中标记或键盘导航。
- 加载状态只替换图标和文案，不改变按钮外框、对齐和语义色。禁止“禁用灰色 -> 白色无边界 -> 最终状态色”的闪烁过程。
- 可见文案已经明确说明用途时，不显示重复的视觉 Tooltip；纯图标或语义不明确的操作才显示 Tooltip。所有操作仍保留可访问名称。
- 宽度不足时使用项目既有的紧凑模式、换行或分组收纳，不把四个控件继续压缩到重叠，也不缩小文字适配视口。

### 工具弹窗标准

设备发送策略弹窗定义紧凑配置弹窗的结构基线：

- 标题图标和标题文字垂直居中，间距 8px；标题保持单行。正文左边缘与标题文字对齐，保留“标题图标宽度 + 8px”的缩进。
- 内容左对齐，说明、字段和操作按 4 / 8 / 12px 节奏分组，不使用卡片嵌套。
- 同一组二元选项的复选框和开关固定在左侧，标题和补充说明排列在其右侧；不得在同一弹窗中一项左置、一项右置。
- 标签和输入可以在当前宽度容纳时放在同一行。设备发送策略的行内标签宽 128px、标签与输入间距 12px；标签使用普通字段文案样式，不单独加粗或放大。
- 设备名、短说明、单个 UUID 和开关说明优先单行；只有信息确实无法容纳时才换行。不可预测的长值使用 `maxLines: 1` 与省略，不反向撑大弹窗。
- UUID、HEX、时间和协议值继续使用等宽字体；说明文字使用普通 UI 字体。
- 校验错误显示在对应输入下方，错误出现后左侧标签和其他字段不能发生不必要的水平或垂直漂移。
- 底部操作右对齐，取消在前、确认在后；两者高 34px、水平内边距 20px、垂直内边距 4px。

### 状态与交互标准

- 默认、hover、focus、active、loading、disabled 和 selected 状态必须共享同一几何外框，状态变化不能引发布局跳动。
- hover 只做轻量表面变化；focus 必须保留可见焦点指示；disabled 仍需看得出控件边界和当前文案。
- 选中、连接、扫描、危险和错误使用语义颜色；颜色不能是唯一信息，必须同时有文字、图标、边框或选中标记。
- 所有弹层和弹窗保留键盘操作、焦点顺序、语义标签和自动关闭/保存校验行为。视觉收紧不能以删除交互能力为代价。
- UI 精细化必须同时检查亮色、暗色、1440px 桌面和 375px 窄屏；紧凑桌面尺寸不能直接套用为移动端触控尺寸。

### 后续 UI 调整方法

1. 先判断新控件属于工具栏、紧凑列表、普通表单还是工具弹窗，不跨层级机械复制尺寸。
2. 优先复用 `app/design` 和现有语义样式；第三方默认值与本基线冲突时，在项目适配层或局部项目组件中处理，不修改 `.pub-cache`。
3. 先统一外框、字号、间距和对齐，再调整颜色与动效，最后检查长文案、加载、禁用和错误状态。
4. Widget 测试应测量实际渲染尺寸、间距和相对位置；只断言构造参数不足以证明第三方组件内部样式已生效。
5. 涉及页面整体、亮暗主题或响应式边界时更新 Golden；只改变弹层内部且已有精确 Widget 断言时，可按影响范围决定是否更新页面 Golden。
6. 修改上述基线控件时，同一变更中更新本节和对应回归测试，避免实现、规范和验收标准分离。

## UI UX Pro Max 结论如何落地

技能检索给出的“极简瑞士式专业工具”方向适合 BLExpert：功能优先、网格清晰、低装饰、强排版、克制状态色、轻量 hover 和可见键盘焦点。

其中“代码深色模式 + 绿色端点强调”的建议只适用于调试运行态，不应取代 BLExpert 的亮色与系统主题。最终采用：

- 亮色主题：默认跟随系统，适合文档、配置和明亮办公环境。
- 暗色主题：高密度收发、长期观测和低照度环境的专业调试模式。
- 状态强调：连接/执行使用主色或绿色，RX/TX 使用不同辅助色，错误使用红色，警告使用琥珀色。
- 字体：UI 使用系统无衬线字体；HEX、UUID、时间、长度、命令码和脚本使用等宽字体。

不采用的建议：将产品整体固定为 OLED 黑色主题、使用明显发光效果、为纯视觉风格引入网页字体下载。这些不符合跨平台 Flutter 工具的离线可用性、亮色主题需求和高密度可读性。

## 组件库选型与迁移边界

结论：已锁定 `shadcn_flutter` 作为唯一 UI 组件体系，应用层全面迁移已完成，不保留 Material 可见控件，也不引入 `fossui`。

| 候选 | 当前结论 | 原因 |
| --- | --- | --- |
| `shadcn_flutter` | 唯一组件体系 | Button、Dialog、Input、Select、Tabs、Navigation、Tooltip、Toast 和 Scrollbar 已覆盖应用 UI；当前 Flutter 3.44.1 / Dart 3.12.1 满足其版本要求。 |
| `fossui` | 暂不引入 | 当前环境虽满足 Flutter >= 3.41.0、Dart ^3.11.5，但库仍处于较早阶段，针对设备树、密集日志列表和复杂配置编辑器的覆盖需额外验证。 |

迁移规则：

- 应用代码不得新增 Material 可见控件或交互表面；需要新控件时优先扩展 `app/design` 或使用 shadcn 原生组件。
- 目录与组件拆分不等于组件库迁移完成；迁移状态以本文件“本轮迁移记录”和实际代码为准。
- 新增 `app/design` 适配层封装候选库，业务界面不直接依赖第三方组件 API；主题颜色、间距、圆角、等宽数据文本和语义约束继续由本项目令牌定义。
- 当前已落地的 shadcn_flutter 组件：`ShadcnApp`、`Scaffold`、`AppBar`、桌面与窄屏导航、Tabs、Tooltip、Toast、DropdownMenu、Select、AlertDialog、TextField、SelectableText、Scrollbar、按钮、开关、复选框、徽章及 Lucide 图标。
- 桌面模式导航已使用 shadcn `NavigationRail`；窄屏底部模式导航迁移到 shadcn `NavigationBar`，同时保留已验证的安全区域、触控尺寸、稳定 key 和键盘/读屏语义契约。
- 语言设置和记录页元数据筛选统一通过 `ToolSelect` 使用 shadcn `Select`；弹层测试使用定时 `pump` 覆盖进出场动画，不依赖持续 ticker 收敛。
- 首个 spike 限定为配置页命令编辑器、设备发送策略确认框和发送编辑器；不得修改 BLE 服务、领域模型、工作区导入导出格式或安全发送策略。
- `lib/app/design` 已提供对话框、输入框、选择器、按钮、选择状态、开关、Tooltip、Toast 和点击行适配边界。工具对话框使用 shadcn `AlertDialog` 与 `DialogConfiguration`，不再保留透明 Material 承载层。
- 应用根使用 `ShadcnApp` 承载主题、国际化、路由、Popover、Tooltip、Menu、Drawer 和 Toast；`ToolTextField`、`ToolSelect`、`ToolButton`、`ToolToggle` 和项目选择控件继续提供业务稳定边界。
- shadcn 亮暗主题必须从同一组项目语义颜色构建，不得依赖默认 Slate 主题，也不得在业务页面复制选中、焦点、禁用和危险状态颜色。
- 调试发送区的模式切换使用紧凑矩形分段控件：高度 36px、圆角 6px、水平内边距 10px；选中态使用项目的 `selectedStrong` 或 `selectedSubtle` 角色，不再把默认 `ButtonStyle.secondary` 直接视为合格选中态。行尾选择器与其保持同高、同边框和 6px 圆角，模式、行尾、直接发送和发送操作在一条工具带中对齐；直接发送开关悬浮说明需要明确写出“跳过协议封包与发送前脚本，仍受设备发送策略约束”。
- 业务界面不得继续复制 `outline/ghost -> secondary` 的选择样式组合；选择按钮、导航项和筛选器应经 `app/design` 的项目级状态样式接入。选中态至少同时改变背景、边框/指示条、文字/图标中的两项。
- 指令集列表采用 12px 面板边距和 8px/6px item 内边距；启用与快捷入口状态必须显示常驻文字标签，状态控件间距为 8px，并与编辑、删除操作明确分组，不能只依赖悬浮提示说明含义。
- 指令编辑弹窗采用“一个字段一行”的标签与控件布局；新建指令使用带图标和文字的主按钮。分组字段保留为可选项，用于指令集与调试快捷指令中的分组显示。参数编辑器在宽屏保持一个参数一行，新参数默认值为空并显示占位提示；已添加参数在数据内容下方显示可点击的参数名称，点击后按当前光标位置插入对应的 `{{key}}`，悬浮提示同时说明实际插入 token。
- 参数行的字段顺序固定为 `key`、名称、类型、默认值、删除；删除操作始终位于行末，类型选择器占满其分配宽度。没有参数时，参数操作区与备注字段保留明确的垂直间距。
- 参数快捷插入只为非空 key 渲染 token；新增空参数仍必须使用稳定的索引 key，连续添加空参数不得产生重复 widget key。参数 item 与新增按钮之间保留 8px 以上的分隔距离，备注标签不因该间距额外下移。
- 已迁移控件需持续通过 Linux 与 Web、窄屏与宽屏、亮暗主题、键盘焦点/屏幕阅读器语义、文本溢出和 Widget 回归；升级 `shadcn_flutter` 时按同一矩阵复测。
- `shadcn_flutter` 当前仍为 `0.0.x`，锁定版本并在升级前审查破坏性变更、依赖体积和测试结果。

## 后续优先级

当前控制台已具备方向筛选、关键字/HEX 搜索、筛选结果导出、来源标识、自动滚动、回到最新和 Inspector 定位；后续重点转为更完整的解析摘要和事务分析。

#### 已完成

- 控制台已支持 TX/RX/SYS/ERR 方向筛选、日志来源与详情定位、自动滚动及保留/丢弃计数。
- 发送区已显示禁用原因、业务载荷长度和最终帧预览；模式与行尾控件统一为 36px 高、6px 圆角的矩形工具控件。
- 设备树已支持搜索和 R/W 能力筛选；Inspector 已展示选中日志的方向、时间、来源、长度、指令、事务 ID 与完整帧。

#### 后续分析增强

- 继续补充更完整的解析摘要和可审查的事务分析。
- Inspector 后续增加 ASCII、解析字段、脚本日志、复制和重发操作。

#### 验收

工程师可在不离开调试模式的情况下，用时间、方向、特征或 HEX 快速定位一帧，查看完整上下文并复制或重发该帧。

### P1：发送编辑器明确“目标、输入、结果、风险”（核心项已完成）

发送入口是最可能影响真实设备的操作，当前仅显示写入特征短 UUID 和普通输入框，反馈与风险表达还不够。

#### 已完成

- 已显示当前写入模式、连接状态、输入校验、业务载荷长度和最终帧预览。
- 输入非法、未连接、未选择写入特征或设备策略拒绝时，按钮禁用并给出明确原因。
- 高风险命令和显式保护命令继续经过真实安全发送路径并弹出确认。

#### 后续增强

- 增加批量发送、重发和发送成功后自动定位 TX 行。
- 继续完善复杂协议和脚本模式下的业务载荷 -> 最终帧解析摘要。

#### 验收

用户不需要猜测数据将写入哪个特征；发送前能看到数据是否合法、长度是多少和是否经过脚本转换。

### P0：配置编辑器提供完整的校验反馈

当前配置模式已拆出工作区、协议、指令和响应映射，但复杂表单仍以即时更新和局部字段编辑为主。协议配置一旦有多个错误，用户需要在不同区域自行定位。

`ui-ux-pro-max` 对表单错误的有效要求是：每个无效字段保留行内错误；提交失败后额外提供可聚焦的错误摘要，并能定位至对应字段。对于 Flutter，应使用语义标签、焦点控制和可访问的错误文本实现，不要只使用 SnackBar 或红色边框。

#### 需要改造

- 配置编辑改为“草稿编辑 -> 显式保存/应用”，避免每一次输入立即改变可运行工作区。
- 顶部显示保存状态：已保存、正在保存、未保存、校验失败。
- 保存失败时显示错误摘要；点击摘要条目自动滚动并聚焦对应字段。
- 每个字段提供具体行内错误，例如：HEX 字节不完整、长度字段缺字节序、参数占位符不存在、响应字段越界、映射字段重叠。
- 协议编辑器提供发送帧/接收帧的结构预览和示例报文验证结果。
- 脚本配置显示执行可用性、信任状态、资源限制和安全警告，不仅显示脚本文本框。
- 指令与映射列表支持多选、批量启用/禁用、批量分组或批量删除，避免逐条操作大型协议库。

#### 验收

用户在配置复杂协议时可清晰看到修改是否已保存、有哪些错误、错误在哪里以及修复后是否通过验证。

### P1：设备与特征树提升扫描效率

现有服务分组与特征操作已可用，但设备区应更接近工程工具中的对象浏览器。

#### 需要改造

- 服务节点可展开/折叠，默认只展开含可读、可写、可订阅属性的服务。
- 特征行使用固定信息顺序：显示名及属性标识、完整 UUID、行内操作；属性标识紧跟名称，不单独占行。
- 属性标识统一为带方向的 `R←`、`W→`、`WNR→`、`N←`、`I←`，分别表示读取、带响应写入、无响应写入、通知和指示，并提供 tooltip 与语义文字。
- 行内操作保留协议常用英文并统一使用 Title Case：`Read`、`Write`、`Write No Response`、`Notify`、`Indicate`。按钮高度为 28px，水平内边距为 6px，使用紧凑的低强调样式。
- `Write` 与 `Write No Response` 是互斥的真实写入模式选择，不使用含义模糊的统一“写入目标”；底层发送、工作区持久化和设备发送策略必须采用用户实际选择的模式。
- 为特征树增加搜索与“仅显示可操作特征”筛选。
- 保留完整 UUID 的复制入口，并在窄空间只显示短 UUID。
- 已订阅、当前写入模式、读取失败和不支持能力必须使用标识加文本/tooltip双重表达。

#### 验收

连接到多服务设备后，用户可在数秒内筛出可用特征、明确当前写入与订阅目标，并获得操作结果反馈。

### P1：Inspector 按“当前对象”而不是“固定分区”工作

当前 Inspector 由快捷命令和映射数据上下堆叠，适合基础场景，但当用户选中日志、特征、命令或数据字段时，它仍缺少针对性详情。

#### 需要改造

- 定义 Inspector 上下文优先级：选中日志 > 选中特征 > 正在编辑命令 > 最新映射数据 > 默认快捷命令。
- 单击日志行时显示帧详情；单击特征时显示属性和订阅控制；单击命令时显示参数、预览与执行历史。
- 快捷命令和映射数据作为默认上下文内容，不占用选中对象详情空间。
- Inspector 顶部显示当前上下文标题、来源和关闭/固定操作。
- 允许用户固定 Inspector 到某个特征或数据映射，避免实时选择变化打断观察。
- 默认映射数据使用自适应网格，每格固定两行：上行显示等宽数据值，下行显示字段名称；映射来源与 CMD 保留在 Tooltip 和语义信息中，不额外占用视觉行。

#### 验收

右侧区域始终回答“我当前选中的对象是什么、能做什么、最近发生了什么”，而不是仅展示固定卡片集合。

### P1：统一工具密度与视觉令牌

现有主题已具有良好基础。下一步不应重换颜色，而应将现有零散数值收敛为统一令牌并在关键组件统一执行。

| 令牌 | 建议值 | 使用原则 |
| --- | --- | --- |
| 页面边距 | 16px 桌面，8px 窄屏 | 外层布局；配置二级页面遵循当前 16px 基线。 |
| 区域工具条高度 | 40px 或 42px | 控制台、Inspector、列表标题 |
| 首页工具栏控件高度 | 36px | 工作区、设备、连接和扫描控件保持同高；桌面基线宽 136px、间距 8px |
| 紧凑控件高度 | 32px | 图标按钮、筛选器、小型下拉框 |
| 常规控件高度 | 40px | 表单、主要按钮 |
| 间距刻度 | 4 / 8 / 12 / 16px | 只使用这四档 |
| 圆角 | 4px 一般表面，6px 对话框 | 不增加大圆角 |
| 分割线 | 1px | 优先分割线而非嵌套卡片 |
| 左侧对象区 | 240px，范围 220-280px | 可折叠或可拖动 |
| Inspector | 320px，范围 300-360px | 可关闭或可拖动 |

交互状态与动效令牌以 [UI shadcn 全面迁移与状态动效修正计划](UI状态与动效修正计划.md) 为准。关键要求是：选择态至少有一个达到 3:1 的非文本指示，普通文字达到 4.5:1；hover/pressed 使用 100-150ms，Switch/选择切换使用 180-220ms，弹层使用 200-300ms，并为减少动态效果提供终态直达分支。

视觉规则：

- 不新增浮动卡片、大阴影、渐变背景、装饰插图或营销式标题。
- 运行态页面使用连续画布和分割线，独立卡片仅用于命令项、临时提示和模态对话框。
- 暗色模式保持当前蓝灰中性表面；避免大面积纯黑和高饱和色块。
- 主色只表达选择与主操作；绿色表示成功/已连接，青绿可用于 RX，蓝色可用于 TX，琥珀色表示待确认或警告，红色表示错误或危险。
- 色彩不得作为唯一状态说明；每个状态都要有文字、图标或语义标签。

### P1：可访问性和键盘效率

现有 tooltip 是正确起点，但工具型桌面应用需要完整的键盘与语义支持。

#### 需要改造

- 所有纯图标按钮使用明确 tooltip 和 `Semantics` 标签；切换类控件同时暴露 selected/pressed/expanded 状态。
- 装饰性图标从语义树中隐藏；有意义但无可见文本的图标必须提供可读标签。
- 列表、树、模式导航、Inspector 和日志详情具备稳定的 Tab 焦点顺序。
- 添加快捷键：扫描、连接/断开、聚焦发送框、发送、清空、切换自动滚动、展开/收起 Inspector。
- 不以 toast/SnackBar 作为唯一错误反馈；输入和配置错误必须保留可定位的行内信息。
- 高对比度下验证状态色、禁用态、焦点环和文本对比度；亮色正文对比度不低于 4.5:1。
- 动效按距离和复杂度使用项目令牌，不把一个时长套用到全部过渡；遵从减少动态效果偏好，语义状态立即更新，动画不能影响数据刷新与焦点定位。

#### 验收

用户仅通过键盘可切换模式、选择设备/特征、输入并发送、浏览日志、打开详情和修复配置错误；屏幕阅读器可理解控件名称、状态与错误。

### P2：记录模式成为会话分析工具

当前“记录”模式已具备有界持久化、方向/特征/指令/文本筛选、书签、JSON 导出和基础 TX-RX 事务关联。下一步应增加分析价值，而不是复制控制台。

- 支持会话命名、开始/结束时间、设备、工作区和协议版本元数据。
- 支持异常帧标记、批量导出和可追溯的脱敏导出选项。
- 将多路通知、设备主动上报和命令执行关联为可审查事务，而不是仅关联 5 秒窗口内首条 RX。
- 大型记录采用分页、虚拟列表或区间加载，避免一次渲染全部日志。

## 响应式规范

### 宽屏：大于等于 1200px

- 保持模式导航 + 设备区 + 控制台 + Inspector 的工具台布局。
- Inspector 默认打开；支持关闭和用户尺寸偏好。
- 每列独立滚动；控制台是视觉主区，不使用页面整体滚动替代控制台滚动。

### 中等宽度：900px 至 1199px

- 保持 shadcn `NavigationRail`，但设备区宽度可缩窄。
- Inspector 默认可收起，可由顶部上下文按钮打开。
- 控制台不得低于可用主区最小宽度；必要时优先收起 Inspector，而不是压缩 HEX 内容。

### 窄屏：小于 900px

- 使用 shadcn `NavigationBar` 保持调试、配置、记录三入口，不保留 Material `NavigationBar`。
- 调试模式不再并排展示设备、控制台与 Inspector；采用当前对象优先的页面栈或底部面板。
- 发送入口和连接状态必须快速可达。
- 日志采用两行紧凑行：首行时间、方向、来源、长度；次行 HEX 摘要。点击打开完整详情。
- 不使用固定高度堆叠区域；全部高度依据可用约束和安全区域计算。
