# BLExpert 阶段总结与下一步计划

## 当前阶段

BLExpert 已从 Flutter 与 BLE 验证原型，推进为具备工作区持久化、参数化指令、响应字段映射和三模式调试工作台的 BLE 协议调试工具。

当前阶段的主线不再是“是否可以收发 BLE 数据”，而是把已建立的配置模型接入安全、可验证的协议执行链路：标准协议封包、接收解帧、连接默认配置、脚本安全边界和可追溯会话记录。

## 已完成内容

### 1. 工程、设计与测试基础

- Flutter 跨平台工程已覆盖 Android、iOS、Windows、macOS、Linux 和 Web。
- 已提供亮色、暗色、跟随系统主题；支持中文、英文和系统语言。
- UI 已完成第一轮信息架构重构：
  - `调试`：设备/特征、控制台与 Inspector。
  - `配置`：工作区、协议、指令、响应映射。
  - `记录`：当前会话日志回顾。
- 桌面使用 `NavigationRail`，窄屏使用 `NavigationBar`；调试模式的 Inspector 可收起。
- `lib/widgets/app_workspace_shell.dart` 已从 `lib/main.dart` 抽出 Shell 边界，但业务 UI 仍有较多代码集中于 `main.dart`。
- 当前 `flutter analyze` 无问题，`flutter test` 共 19 项通过。

### 2. BLE 通信与平台适配

- 使用 `universal_ble` 完成 BLE Central 主链路。
- 已支持扫描、连接、断开、服务/特征发现、Read、Write、Write without response、Notify 和 Indicate。
- 用户可手动选择写入目标及通知/指示订阅目标，包含仅支持 Write without response 的特征。
- 保留 Mock 蓝牙服务，支持 Widget 测试和无真实设备演示。
- Linux/BlueZ：处理临时信任、停止扫描后连接和真实 GATT 特征展示等问题。
- Web Bluetooth：支持用户配置服务 UUID，处理浏览器服务授权和扫描/连接竞态；Web 不执行 JavaScript 协议脚本。

### 3. 工作区、指令和响应映射

- `Workspace` 已聚合协议定义、脚本配置、指令、响应映射与元数据。
- `WorkspaceManager` 通过 `shared_preferences` 保存工作区列表和活动工作区，键名为 `blexpert.workspace-store.v1`。
- 完整工作区支持 JSON 导入、导出和旧结构兼容读取。
- `CommandDefinition` 支持 HEX/文本载荷、启用状态、快捷入口和参数列表。
- HEX 指令通过 `{{key}}` 占位符扩展参数，支持整数、HEX、ASCII、UTF-8、布尔、枚举和当前日期/时间字节。
- `ResponseMapping` 以 `CMD` 匹配，字段偏移从解码后的 `DATA` 第 0 字节开始，可映射数值、字符串、枚举、位域、比例和单位。
- Inspector 已显示快捷指令和最近一次成功映射的语义字段。

### 4. 协议与脚本配置

- `ProtocolDefinition` 支持独立的发送/接收协议片段。
- 协议片段支持固定 HEX、业务载荷、长度、序号和校验；已定义 XOR、SUM8、CRC8、CRC16-MODBUS、CRC16-CCITT、CRC32 等算法枚举。
- 原生平台通过 `flutter_js` 运行 `beforeSend(context)` 和 `afterReceive(context)`。
- 脚本提供 HEX、字节转换、XOR、SUM、CRC 和 MD5 内置函数。
- 发送路径已调用 `beforeSend`，接收通知路径已调用 `afterReceive`，并保留脚本日志。

## 当前关键边界与风险

### 协议执行链路尚未完成

- 标准协议定义还没有对应的 `PacketEncoder`；长度填充、序号生成、校验计算和最终帧拼装没有接入发送路径。
- 当前参数化指令生成的是业务载荷。数值参数固定使用大端编码，尚没有按命令或协议配置覆盖字节序。
- 当前接收数据没有通用接收缓冲、粘包/拆包、帧头同步、长度判断、帧尾判断和 CRC 校验。
- 响应映射依赖脚本或未来解帧层传入稳定的 `CMD/DATA`；原始通知不会自动按标准协议映射。

### 脚本安全 P0 未完成

- 导入工作区会直接恢复 `ScriptConfig.enabled`，没有未信任状态和首次启用确认。
- `flutter_js` 执行目前没有可靠的超时、可终止隔离、输入输出上限和日志/队列预算。
- 脚本返回的发送帧缺少发送策略、最大长度和完整合法性验证。
- 在整改完成前，AI 或第三方导入脚本均不能视作安全可执行内容。

详见 [脚本执行安全评估与整改计划](脚本执行安全评估与整改计划.md)。

### 工作区与会话沉淀仍不完整

- 工作区尚未保存默认服务 UUID、写入特征和订阅特征，重新连接后仍需手动选择。
- 导入导出没有版本迁移、局部导入、冲突处理或脚本信任边界。
- 日志目前不设持久化、筛选、书签、环形缓冲或正式导出策略。

### UI 第二轮优化尚未开始

- 当前三模式架构已稳定，但控制台仍是线性日志，缺少筛选、帧详情与回到最新行为。
- 配置仍偏即时编辑，缺少草稿、保存状态、字段级校验摘要和危险发送确认。
- 设备树筛选、Inspector 上下文详情、键盘快捷键和完整语义可访问性仍待完成。

详见 [UI 设计规范与下一轮改造方向](BLExpert_UI设计规范与改造方向.md)。

## 下一步计划

### P0：完成协议执行与安全基础

1. 建立纯 Dart `PacketEncoder` 和单元测试，完成标准协议的长度、序号、校验和帧拼装。
2. 将标准协议编码接入手动发送和快捷指令；控制台同时记录业务载荷、最终帧和编码错误。
3. 实现接收缓冲与解帧，处理粘包、拆包、同步和校验失败恢复。
4. 为脚本增加未信任状态、导入禁用、首次启用确认、输入/输出/日志限制和不阻塞 UI 的可终止执行方案。
5. 补齐工作区默认连接目标，让设备连接后可恢复服务、写入和订阅选择。

### P1：提升工具可用性与可追溯性

1. 控制台支持方向/特征/HEX 筛选、帧详情、复制/重发、回到最新和有限日志缓存。
2. 配置引入草稿、显式保存、字段级校验和错误摘要。
3. Inspector 改为选中日志、特征、命令和数据字段驱动的上下文视图。
4. 会话记录支持持久化、筛选、书签、导出和命令-RX-映射关联。
5. 拆分 `main.dart` 中的调试、配置、记录、控制台和 Inspector 组件。

### P2：AI 配置助手与发布准备

1. 先实现协议文档导入草案、校验、证据和用户确认，再考虑模型接入。
2. MVP 使用用户自配模型/API Key 的应用内导入向导；MCP 作为后续外部 Agent 集成层。
3. 完成 Android、iOS、Windows、macOS、Linux 和 Web 的 BLE 真实设备回归与发布检查。

AI 功能的边界与方案详见 [AI 协议文档自动配置方案评估](BLExpert_AI协议文档自动配置方案评估.md)。
