# BLExpert 阶段总结与下一步计划

## 当前阶段：BLE 基础通信闭环已完成，正在进入协议配置与脚本协议阶段

截至当前阶段，BLExpert 已经从 Flutter 初始骨架推进到可用于真实设备调试的跨平台 BLE 工作台。应用已具备扫描、连接、服务/特征发现、读写、通知/指示订阅和通信日志等基础闭环，并且已经开始把“单次 BLE 收发”升级为“可复用的工作区协议配置”。

当前重点不再是验证 BLE 是否可用，而是稳定工作区中的协议、指令、脚本、设备连接配置和后续数据映射模型，让调试过程能够沉淀、复用和导入导出。

## 已完成内容

### 工程与界面

- 已建立跨平台 Flutter 工程，目标覆盖 Android、iOS、Windows、macOS、Linux 和 Web。
- 已实现深色、浅色和跟随系统主题。
- 已实现中文、英文和跟随系统语言的国际化能力。
- 已建立 README、项目说明、Agent 协作说明、阶段总结和开发计划文档。
- 调试台已具备工作区区域、设备选择、连接控制、特征面板、通信控制台、快捷指令和数据展示入口。
- 当前界面正在从“协议配置”和“脚本协议”分散入口，调整为统一的协议配置入口，支持标准协议模式与脚本协议模式切换。

### BLE 通信

- 已采用 `universal_ble` 完成 BLE Central 基础主链路。
- 已支持设备扫描、连接、断开、服务发现和特征发现。
- 已支持 Read、Notify、Indicate、Write 和 Write without response。
- 用户可以自行选择写入目标特征和通知/指示订阅特征。
- 已修复仅支持 Write without response 的特征无法作为写入目标的问题。
- 已支持带时间戳的收发日志和 HEX 输入输出。
- 已保留 Mock 蓝牙服务，方便桌面/Web 预览和 Widget 测试。

### Linux / BlueZ 适配

- 已处理 BlueZ 设备对象刷新、临时信任设置、连接和通知相关问题。
- Linux 连接未配对 BLE 设备时，会通过系统能力设置临时信任状态。
- 当前方案仅使用 BlueZ 通过 D-Bus 真实暴露的服务和特征，不再合成 `1800/2A00`。
- 不再使用会干扰长期连接的 `gatttool` 读取方式。
- 连接前会停止扫描，降低 BlueZ 扫描与 GATT 连接之间的竞态风险。

### Web Bluetooth 适配

- 已支持 Chrome Web Bluetooth 调试路径。
- 已移除所有特定设备和厂商 UUID 硬编码。
- Web 服务 UUID 由用户在设备选择前配置，支持 16 位、32 位和 128 位 UUID，并自动标准化为 128 位格式。
- 已处理 Chrome/Linux 实验性广告监听造成 BlueZ 持续扫描、阻塞 GATT 连接的问题。
- 已处理浏览器已经连接、Flutter 页面仍显示连接中的连接事件竞态。
- 特征发现已直接使用浏览器 GATT API，与浏览器安全模型保持一致。

### 工作区基础能力

- 已建立 `Workspace` 数据模型，包含工作区元信息、设备列表、协议配置、脚本配置和指令集。
- 已建立 `WorkspaceManager`，支持内存中的工作区列表、活动工作区切换、增删改和 JSON 导入/导出基础能力。
- 当前工作区管理仍以页面内存为主，尚未完成本地文件持久化。
- 工作区已经开始承载协议、脚本和指令配置，但设备默认服务、默认特征、响应定义、数据映射等仍需补齐。

### 指令集能力

- 已建立 `CommandDefinition`，支持名称、分组、HEX/文本载荷、备注、启用状态和快捷入口标记。
- 左侧“指令集”支持新增、编辑、删除、启用/禁用和快捷入口选择。
- 右侧“快捷指令”只展示已启用且标记为快捷入口的指令。
- 快捷指令复用当前选择的写入特征进行发送。
- 已完成指令集在工作区 JSON 中的往返序列化和旧数据兼容测试。

### 协议配置能力

- 已建立 `ProtocolDefinition` 和 `ProtocolSegment` 模型。
- 协议片段已支持固定 HEX、业务载荷、长度字段、序号字段和校验字段。
- 已定义字节序、计算范围和多种校验算法枚举：XOR、SUM8、CRC8、CRC16-MODBUS、CRC16-CCITT、CRC32。
- UI 已提供协议定义配置入口，并正在整合标准协议模式和脚本协议模式。
- 当前协议配置主要处于模型和编辑层，尚未完整接入标准协议封包、长度填充、序号生成和校验计算执行链路。

### 脚本协议能力

- 已建立 `ScriptConfig` 和脚本引擎服务抽象。
- 原生平台已通过 `flutter_js` 接入 JavaScript 运行时。
- 已定义 `beforeSend(context)` 和 `afterReceive(context)` 的初版脚本契约。
- 发送前脚本可以将业务载荷转换为完整 BLE 帧，接收后脚本可以对完整帧进行处理并输出日志。
- Web 平台当前保留脚本配置能力，但不执行 JavaScript 协议脚本，并给出明确提示。
- 脚本阶段已开始落地，但还需要补充错误展示、超时保护、示例脚本和更多测试。

## 当前边界

- 当前已实现 BLE，经典蓝牙 SPP 尚未接入。
- 工作区仍以内存状态为主，本地持久化、单工作区导入导出、版本迁移尚未完成。
- 标准协议配置尚未形成完整执行闭环，仍缺少统一 `PacketEncoder`。
- 参数化指令模型尚未完成，当前指令仍主要是固定 HEX/文本载荷。
- 接收解帧、粘包/拆包、响应定义和校验失败恢复策略尚未完成。
- 数据映射、结构化字段展示、图表和日志导出尚未开始。
- Web Bluetooth 受浏览器安全模型限制，只能访问设备选择前通过 `optionalServices` 声明过的服务。
- `lib/main.dart` 当前体量较大，后续继续增加协议、映射和持久化能力前需要逐步拆分。

## Web Bluetooth 使用约束

Web Bluetooth 受浏览器安全模型限制，网页只能访问设备选择前通过 `optionalServices` 明确声明的服务。

- 顶部 Web 服务 UUID 配置中填写的是服务 UUID，不是特征 UUID。
- 需要填写本工作区将使用的全部服务 UUID。
- 修改服务 UUID 后必须重新扫描，并在 Chrome 设备选择器中重新选择设备，浏览器才会重新授予服务访问权限。
- 浏览器不会向网页暴露未声明服务的特征，无法在连接后无权限地枚举完整 GATT 数据库。
- Web 端目前不执行 JavaScript 协议脚本，原始 BLE 调试能力不受影响。

## 下一步计划

### 1. 收尾协议配置 UI 重构

- 确认标准协议模式和脚本协议模式在同一协议配置页内的交互稳定。
- 保证协议名称、描述、收发片段和脚本内容切换后不会丢失。
- 补齐相关中英文文案。
- 保持现有 Widget 测试通过，并根据新交互补充测试。
- 收敛当前较大的未提交改动，形成阶段性提交。

### 2. 补齐参数化指令模型

- 扩展 `CommandDefinition`，增加命令码、载荷模板、协议关联、协议覆盖项和参数列表。
- 定义参数类型：整数、HEX、ASCII/UTF-8、布尔和枚举。
- 定义参数默认值、范围、固定长度和可变长度规则。
- 为可变长度参数补充长度前缀、结束符、TLV 和剩余载荷等边界规则。
- 优先完成模型、JSON 序列化和单元测试，再完善复杂 UI。

### 3. 建立标准协议封包基础库

- 新增 HEX、字节序、ASCII/UTF-8 编码工具。
- 实现 XOR、SUM8、CRC8、CRC16-MODBUS、CRC16-CCITT 和 CRC32。
- 实现统一 `PacketEncoder`，支持固定头、业务载荷、长度字段、序号字段、校验字段和固定尾。
- 标准协议配置错误时必须阻止发送，并在控制台输出明确原因。
- 未配置协议的旧指令继续按原始 HEX/文本行为发送。

### 4. 接入发送处理链路

- 标准协议模式下，快捷指令和手动发送应通过 `PacketEncoder` 生成完整 BLE 帧。
- 脚本协议模式下，继续由 `beforeSend(context)` 接管整帧编码。
- 通信控制台同时保留原始输入、最终发送帧和脚本/编码日志。
- 脚本异常或编码失败不得隐藏原始输入，也不得写入不完整数据。

### 5. 建立接收解帧和响应定义

- 为每个连接/特征建立接收缓冲。
- 支持一次通知多帧和一帧拆成多次通知。
- 按接收协议配置完成头部同步、长度判断、尾部判断和校验验证。
- 定义响应类型，支持按来源特征、命令码或匹配模板识别响应。
- 控制台区分原始通知、完整协议帧和解析错误。

### 6. 推进数据映射与持久化

- 在接收解帧稳定后，定义 `DataMapping` 和字段规则。
- 支持温度、电量、计数器、状态位、枚举状态等基础字段展示。
- 将设备默认服务、默认写入特征、默认订阅特征迁移到工作区配置。
- 在协议、指令、脚本、设备和映射模型稳定后，实现本地 JSON 持久化、导入导出和版本迁移。
