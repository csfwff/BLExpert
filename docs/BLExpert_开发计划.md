# BLExpert 开发计划

## 当前基线

当前版本已具备跨平台 BLE 调试的基础闭环：扫描、连接、断开、服务与特征发现、读写、通知/指示订阅，以及带时间戳的通信日志。左侧工作区已提供指令集管理；右侧快捷指令仅用于执行用户标记为快捷入口的已启用指令。

下一阶段的目标是把单次 BLE 收发升级为可复用的设备协议配置。工作区是这些配置的聚合容器，而不是先独立完成的功能。配置模型稳定后再完成持久化和导入导出，避免频繁破坏工作区文件兼容性。

## 设计原则

- 原始 BLE 收发数据始终写入通信控制台；协议拆包、校验、脚本或映射失败均不得隐藏原始数据。
- 发送和接收共享一套协议配置模型，但分别配置帧结构，不能假设请求与响应完全对称。
- 协议头尾、长度、包序号和校验码属于协议定义；业务命令只描述命令码、载荷模板和参数。特殊指令可显式覆盖默认协议规则。
- 简单协议优先使用可视化配置；TLV、加密、动态签名等复杂逻辑由脚本扩展处理。
- 左侧负责配置和管理，右侧负责调试、执行、结果展示和后续快捷入口。

## 阶段 1：指令集基础管理（已完成）

### 已交付

- `CommandDefinition` 支持名称、分组、HEX/文本载荷、备注、启用状态和快捷入口标记。
- 左侧“工作区 > 指令集”支持新增、编辑、删除、启用/禁用及快捷入口选择。
- 右侧“快捷指令”只显示已启用且标记为快捷入口的指令，并复用当前写入特征发送。
- 完成工作区 JSON 中指令集的往返序列化及旧数据兼容测试。

### 后续补充

- 指令排序、分组筛选与搜索。
- 指令复制和导入预览。

## 阶段 2：协议定义与参数化指令模型

### 目标

建立工作区可配置的收发协议模型，并让指令支持用户输入的固定或不定长参数。此阶段优先稳定数据模型、JSON 序列化和编辑入口，不改变现有 BLE 连接能力。

### 实现内容

- 新增 `ProtocolProfile`，支持名称、描述和收发两个方向的帧定义。
- 帧定义支持协议头、协议尾、长度字段、包序号字段、校验配置和字节序。
- 长度字段明确位置、宽度、字节序、计算范围和是否包含自身；校验字段明确算法、位置、字节序和计算范围。
- 内置 XOR、SUM8、CRC8、CRC16-MODBUS、CRC16-CCITT 和 CRC32；AES、复杂校验和动态规则留给脚本。
- 扩展 `CommandDefinition`：关联协议定义、命令码/载荷模板、协议覆盖项和参数列表。
- 参数支持 `uint8`、`int8`、`uint16`、`int16`、`uint32`、`int32`、HEX、ASCII/UTF-8、布尔和枚举；可配置默认值、范围、固定长度或最小/最大字节数。
- HEX、ASCII/UTF-8 参数允许不定长，其编码后的实际字节数由协议层的长度字段自动计算。
- 可变长度参数支持四种边界规则：前置长度字段、结束符、TLV 长度值结构和“剩余载荷”。连续出现多个不定长参数时必须选择明确边界规则，不能仅依赖参数排列顺序。
- 参数模型记录长度前缀的宽度和字节序、结束符 HEX、TLV 类型值（可选）及剩余载荷位置，保证发送编码与接收解析使用同一语义。
- 在左侧新增“协议”配置入口，在指令编辑器增加参数配置和模板校验。
- 建立模型 JSON 版本与向后兼容规则，未配置协议的既有裸载荷指令继续可用。

### 交付物

- 协议定义、帧定义、校验和指令参数数据模型。
- 左侧协议配置页与参数化指令编辑页。
- 模型序列化、模板校验、数值编码和校验算法单元测试。

### 验收标准

- 用户可配置一条带头、长度、序号、CRC 和尾部的发送协议。
- 用户可定义含不定长 HEX 或文本参数的指令，且无需手动填写长度或 CRC。
- 用户可为不定长参数配置长度前缀、结束符、TLV 或剩余载荷规则；连续变长参数没有边界配置时应拒绝保存并说明原因。
- 原有纯 HEX/文本指令在没有协议定义时仍按原行为发送。

## 阶段 3：脚本协议模式与发送前/接收后处理链路

### 目标

为配置模型无法完整覆盖的私有协议提供脚本协议模式，并让发送前与接收后脚本真实参与 BLE 收发链路。

### 实现内容

- 在工作区中增加脚本协议模式开关、发送前脚本和接收后脚本配置。
- 定义稳定脚本契约，如 `beforeSend(context)` 与 `afterReceive(context)`；允许脚本直接接管整帧编码与解码。
- 左侧新增脚本协议页，支持样例脚本装载、编辑和保存。
- 原生平台接入 JavaScript 运行时，发送前脚本可将业务载荷转换为完整 BLE 帧，接收后脚本可将完整帧还原为业务载荷。
- Web 平台保留脚本编辑能力，并明确提示当前平台不执行脚本，避免影响既有 Web BLE 调试能力。
- 通信日志同时保留脚本输出帧和脚本执行日志，便于验证协议行为。
- 以带随机 index、CRC、转义和异或加密的真实设备协议作为首个样例模板。

### 验收标准

- 一条发送前脚本可把 `[CMD, DATA...]` 转换为完整 BLE 帧并实际发送。
- 一条接收后脚本可把完整 BLE 帧解密、验 CRC，并输出业务载荷和日志。
- 脚本异常、缺失函数或当前平台不支持运行时，应用仍保留原始收发和明确错误信息。

## 阶段 4：接收解帧、校验与响应定义

### 目标

将底层通知/指示字节流恢复为稳定的协议帧，为响应匹配和数据映射提供可信输入。

### 实现内容

- 新增每个连接/特征独立的接收缓冲，处理一次通知包含多帧和一帧拆成多次通知的情况。
- 按接收帧定义完成头部同步、长度判断、尾部判断、序号读取和校验码验证。
- 支持固定长度、长度字段和包尾三种基础完整帧判断；无法配置的拆包规则由后续脚本扩展。
- 定义校验失败、长度异常和无法同步时的策略：记录解析错误、保留原始数据、尝试重新同步下一帧。
- 新增 `ResponseDefinition`，可按来源特征、响应命令码或匹配模板关联请求指令和响应类型。
- 在控制台区分原始通知与已解析协议帧，显示校验状态但不移除原始记录。

### 验收标准

- 分包和粘包场景能恢复出正确的完整帧。
- CRC 错误帧会清晰标记，后续合法帧仍能继续解析。
- 可按响应命令码识别一条完整响应，但尚未要求展示业务字段。

## 阶段 5：数据映射模型与语义化展示

### 目标

将已校验的响应帧映射为字段值，并在右侧数据区结构化展示。此阶段先完成规则映射和最新值，不直接投入复杂图表编辑器。

### 实现内容

- 定义 `DataMapping` 与字段规则：来源响应、偏移、长度、数据类型、字节序、比例、偏移量、单位、枚举表和位域。
- 映射从已解帧的有效载荷开始计算，避免把协议头、长度和 CRC 混入业务字段偏移。
- 支持温度、电量、计数器、状态位、枚举状态等基础映射。
- 左侧提供映射配置和样本 HEX 预览；右侧数据页显示最新值、更新时间、来源特征、响应类型和原始帧。
- 建立字段时序缓存接口，为图表预留采样时间和值；图表绘制作为该阶段的后续小项。
- 映射异常仅记录错误，不能中断控制台日志、接收解帧或其他字段更新。

### 验收标准

- 收到一帧合法响应后，右侧数据页能更新对应字段。
- 对包含温度、电量和状态位的示例帧，比例、单位和字节序正确。
- 映射错误时，原始通知和完整帧仍可检查。

## 阶段 6：参数化编码与标准协议封包

### 目标

为无需脚本即可描述的标准协议补齐参数化编码、长度填充、序号生成和内置校验封包能力。

### 实现内容

- 实现统一 `PacketEncoder`：参数校验、模板渲染、命令载荷编码、长度填充、序号递增、校验计算和片段拼装。
- 右侧快捷指令在有参数时打开参数输入界面；无参数指令保持一键发送。
- 标准协议模式与脚本协议模式并存：标准协议走内建编码，脚本协议由脚本接管整帧。
- 对不定长参数、长度前缀/结束符/TLV 编码、超出范围、奇数 HEX 长度、长度字段溢出和校验计算范围补充测试。

### 验收标准

- 常用数值、枚举、HEX 与文本参数可正确编码。
- 改变不定长参数长度后，参数边界字段、整包长度字段和 CRC 自动更新。
- 标准协议配置错误不会向设备写入不完整数据。

## 阶段 7：设备连接配置

### 目标

让工作区记录设备连接所需的 BLE 参数，并在连接后恢复调试状态。

### 实现内容

- 增加设备名称、协议类型、Web 服务 UUID、默认写入特征和默认订阅特征配置。
- 将 Web 服务 UUID 从页面临时状态迁移到工作区设备配置，禁止内置特定设备 UUID。
- 支持从已发现的服务和特征一键写入工作区默认配置。
- 连接成功后自动恢复写入目标和订阅选择；平台限制或失败需记入控制台。

### 验收标准

- 切换工作区后，Web 服务 UUID 和默认特征选择同步变化。
- 已保存的默认订阅会在连接后恢复，失败时有可追踪日志。

## 阶段 8：工作区持久化、导入导出与版本迁移

### 目标

在协议、指令、响应、映射、脚本和设备模型稳定后，形成可协作的版本化工作区文件。

### 实现内容

- 整合工作区元信息、设备配置、协议定义、指令集、响应定义、映射和脚本。
- 使用本地 JSON 文件保存工作区列表和活动工作区，加入版本字段、迁移和错误恢复机制。
- 支持新建、复制、删除、导入、导出单个工作区，并对导入文件执行结构和版本校验。
- 提供至少一个可直接连通的示例工作区及团队共享说明。

### 验收标准

- 重启应用后工作区配置保持不变。
- 导出的工作区可在同版本应用导入并恢复协议与指令行为。
- 旧格式工作区可迁移或给出明确的不可兼容提示。

## 阶段 9：跨平台回归与发布准备

### 实现内容

- 补充模型、编码、解帧、映射、脚本和服务层测试。
- 建立 Linux、Android、iOS、Windows、macOS 和 Web 的真机回归清单。
- 覆盖扫描、连接、重连、特征发现、订阅、读写、Web 服务权限、长包收发和工作区导入导出。
- 整理用户文档、协议配置示例和故障排查说明。

### 验收标准

- `flutter analyze`、单元测试、Widget 测试和目标平台构建全部通过。
- 每个平台均有可追踪的真实设备回归结果。

## 推荐的近期执行顺序

1. 阶段 2：协议定义与参数化指令模型。
2. 阶段 3：脚本协议模式与发送前/接收后处理链路。
3. 阶段 4：接收解帧、校验与响应定义。
4. 阶段 5：数据映射模型与语义化展示。
5. 阶段 6：参数化编码与标准协议封包。
6. 阶段 7：设备连接配置。
7. 阶段 8：持久化、导入导出和版本迁移。

数据映射的模型会在阶段 5 落地；完整字段展示建立在接收解帧与校验完成之后。该顺序确保语义字段始终基于可信的完整协议帧，同时保留原始 BLE 数据供排障使用。
