# BLExpert 开发计划

## 当前基线

BLExpert 已完成跨平台 BLE 调试的基础闭环：扫描、连接、断开、服务与特征发现、Read、Write、Write without response、Notify、Indicate，以及带时间戳的通信日志。项目已从“验证蓝牙收发可行”进入“沉淀可复用协议配置”的阶段。

当前已完成的重点能力：

- Flutter 跨平台调试工作台、中文/英文国际化和明暗主题。
- BLE Central 主链路，以及 Linux / BlueZ 和 Web Bluetooth 的关键兼容适配。
- 工作区基础模型、内存工作区管理和 JSON 导入/导出基础能力。
- 指令集基础管理、快捷指令和相关 JSON 往返测试。
- `ProtocolDefinition` / `ProtocolSegment` 协议模型及协议配置入口。
- 原生端 JavaScript 脚本协议初版执行链路；Web 端保留脚本配置但不执行脚本。

当前正在进行的是统一“标准协议”和“脚本协议”的配置入口，使协议配置成为后续参数化指令、封包、解帧和数据映射的共同基础。

## 设计原则

- 原始 BLE 收发数据必须始终写入通信控制台；协议拆包、校验、脚本或映射失败都不能隐藏原始数据。
- 标准协议和脚本协议并存：简单协议优先使用可视化配置，复杂私有协议通过脚本扩展。
- 发送和接收可共用协议配置框架，但帧结构必须分别配置，不能假设请求和响应完全对称。
- 协议头尾、长度、序号和校验属于协议定义；业务命令描述命令码、载荷模板和参数。
- 工作区是协议、指令、脚本、设备连接配置、响应定义和数据映射的聚合容器。
- `lib/main.dart` 当前体量较大，后续功能扩展时应同步拆分 UI 组件和服务层逻辑。

## 阶段 3：统一协议配置入口（进行中）

### 目标

将标准协议模式和脚本协议模式统一到同一个协议配置入口中，避免“协议定义”和“脚本协议”分散管理。用户应能在同一配置页内选择标准协议或脚本协议，并编辑对应配置。

### 已具备基础

- 已建立 `ProtocolDefinition` 和 `ProtocolSegment`。
- 协议片段已支持固定 HEX、载荷、长度、序号和校验。
- 已定义字节序、计算范围和校验算法枚举。
- 已建立 `ScriptConfig`。
- 原生平台已通过 `flutter_js` 接入 JavaScript 运行时。
- Web 平台保留脚本配置，但不执行脚本并给出提示。
- 脚本运行时预置 `hexToBytes`、`bytesToHex`、`uintToHex`、`xorBytes`、`sum8`、`crc8`、`crc16Modbus`、`crc16Ccitt`、`crc32`、`md5Hex` 和 `md5Text`，用户脚本可直接调用。

### 近期任务

- 收尾统一协议配置页的 UI 交互。
- 确认标准协议/脚本协议切换不会丢失编辑内容。
- 补齐中英文文案并更新 Widget 测试。
- 在脚本协议页面展示内置工具函数、参数格式和返回值约定。
- 将当前未提交改动整理为阶段性提交。

### 验收标准

- 用户可在同一入口选择标准协议或脚本协议。
- 标准协议可编辑名称、描述、发送帧片段和接收帧片段。
- 脚本协议可编辑启用状态、发送前脚本和接收后脚本。
- Web 端明确提示脚本不执行，但不影响 BLE 调试。
- `flutter analyze` 和 `flutter test` 通过。

## 阶段 4：参数化指令模型

### 目标

把当前固定 HEX/文本指令升级为可参数化的业务命令，为后续自动封包和响应映射打基础。

### 实现内容

- 扩展 `CommandDefinition`：命令码、载荷模板、协议关联、协议覆盖项和参数列表。
- 定义参数类型：`uint8`、`int8`、`uint16`、`int16`、`uint32`、`int32`、HEX、ASCII/UTF-8、布尔、枚举。
- 支持默认值、取值范围、固定长度、最小/最大字节数。
- 支持可变长度参数边界规则：长度前缀、结束符、TLV 和剩余载荷。
- 连续多个不定长参数没有边界规则时必须拒绝保存并说明原因。
- 建立模型 JSON 版本和向后兼容规则。

### 验收标准

- 原有纯 HEX/文本指令在无协议和无参数时保持原行为。
- 参数化指令可以完成 JSON 往返。
- 非法参数配置能够被拒绝并给出明确原因。

## 阶段 5：标准协议封包与发送链路

### 目标

为无需脚本即可描述的协议实现内建封包能力，让参数化指令能够自动生成完整 BLE 帧。

### 实现内容

- 新增 HEX、ASCII/UTF-8、字节序工具。
- 实现 XOR、SUM8、CRC8、CRC16-MODBUS、CRC16-CCITT、CRC32。
- 实现 `PacketEncoder`：参数校验、模板渲染、长度填充、序号生成、校验计算和片段拼装。
- 标准协议模式下，手动发送和快捷指令通过 `PacketEncoder` 生成最终帧。
- 脚本协议模式下，继续由 `beforeSend(context)` 接管整帧编码。
- 控制台同时记录原始输入、最终发送帧和编码/脚本日志。

### 验收标准

- 带头、长度、序号、CRC 和尾部的发送协议可正确封包。
- 改变不定长参数后，长度字段和校验字段自动更新。
- 编码失败时不会向设备写入不完整数据。

## 阶段 6：脚本协议增强与安全加固

### 目标

完善脚本协议模式，使复杂私有协议可通过脚本可靠接入收发链路；同时建立导入信任边界、资源预算和运行时隔离，确保脚本能力仅在可控范围内运行。

### P0 安全前置条件

- 导入工作区中的脚本必须默认禁用，并标记为未信任。
- 用户首次启用导入脚本时，必须明确确认脚本来源和执行风险。
- 为脚本输入、输出、日志、日志缓存和接收任务队列设置上限。
- 发送前校验脚本生成帧的合法 HEX、最大长度和发送策略；不符合要求时拒绝写入。
- 采用可超时、可终止且不阻塞 UI 的执行方案；不能仅依赖 `try/catch`、`Future` 或 Dart `Timer` 处理死循环。

在 P0 完成前，不开放将第三方工作区或公共示例中的脚本视为可直接执行内容的使用路径。

### 实现内容

- 固化 `beforeSend(context)` 和 `afterReceive(context)` 脚本契约。
- 增加帧头帧尾、CRC、随机序号、转义和异或加密等示例脚本。
- 增加脚本执行日志、输入输出预览和错误提示。
- 按工作区隔离或重置 JavaScript Runtime，防止全局状态污染。
- 增加脚本异常、缺失函数、非法 HEX、超长输出、超量日志、死循环和高频通知等测试。
- 审计 `flutter_js` 在各原生目标平台暴露的宿主能力。
- 明确 Web 端不执行脚本时的用户提示。

### 验收标准

- 发送前脚本可把业务载荷转换为完整 BLE 帧并实际发送。
- 接收后脚本可处理完整 BLE 帧并输出业务载荷和日志。
- 脚本异常、超时或资源超限不会中断原始日志记录、冻结 UI 或写入未校验数据。
- 导入含已启用脚本的工作区后，脚本仍为未信任且禁用。
- 工作区之间不存在脚本全局状态或内建函数污染。

详见 `docs/脚本执行安全评估与整改计划.md`。

## 阶段 7：接收解帧、校验与响应定义

### 目标

将底层通知/指示字节流恢复为稳定协议帧，为响应匹配和数据映射提供可信输入。

### 实现内容

- 为每个连接/特征建立独立接收缓冲。
- 支持一次通知包含多帧和一帧拆成多次通知。
- 按接收帧定义完成头部同步、长度判断、尾部判断、序号读取和校验码验证。
- 定义校验失败、长度异常和无法同步时的恢复策略。
- 新增 `ResponseDefinition`，按来源特征、响应命令码或匹配模板关联响应类型。
- 控制台区分原始通知、完整协议帧和解析错误。

### 验收标准

- 粘包和拆包场景能恢复出正确完整帧。
- CRC 错误帧会清晰标记，后续合法帧仍能继续解析。
- 可按响应命令码识别完整响应。

## 阶段 8：数据映射与语义化展示

### 目标

将已校验的响应帧映射为字段值，并在右侧数据区结构化展示。

### 实现内容

- 定义 `DataMapping` 和字段规则。
- 支持来源响应、偏移、长度、数据类型、字节序、比例、偏移量、单位、枚举表和位域。
- 映射从已解帧的有效载荷开始计算，避免协议头、长度、CRC 混入业务字段偏移。
- 支持温度、电量、计数器、状态位、枚举状态等基础字段。
- 建立字段时序缓存接口，为后续图表预留。

### 当前实现状态

- 已完成参数化指令的第一版：指令业务载荷使用 `{{key}}` 占位符，快捷发送行内显示所有参数输入。支持整数、HEX、ASCII、UTF-8、布尔、枚举，以及独立的当前年、月、日、时、分、秒字节。时间字段可按协议要求自由排列。
- 已完成响应映射的第一版：按解码后的 CMD 匹配响应，字段偏移相对于 DATA 的第 0 字节；支持整数、HEX、ASCII、UTF-8、布尔、枚举、位域、字节序、比例、数值偏移和单位。
- 已接入右侧“数据”页：保留原始收发记录，同时显示最近一次成功映射的语义字段。
- 已随工作区持久化参数定义与响应映射；旧工作区缺失对应字段时自动按空配置读取。

### 处理顺序

```text
参数输入 -> 指令业务载荷 -> 发送前协议脚本/普通协议 -> BLE 写入
BLE 接收 -> 接收后协议脚本 -> CMD/DATA -> 响应映射 -> 结构化数据展示
```

协议层负责帧头帧尾、包序号、校验、转义和加密；参数与数据映射不直接操作这些协议字段。复杂条件、动态长度、TLV 或嵌套数据仍应先在接收后脚本中转换为稳定的 CMD/DATA，再交给静态映射展示。
