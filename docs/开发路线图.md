## 当前基线

BLExpert 已完成 BLE Central 基础调试闭环、标准协议收发链路和第一轮工作台信息架构重构。当前仓库具备：

- BLE 扫描、连接、GATT 发现、读写和通知/指示订阅。
- 三模式 UI：调试、配置、记录。
- 工作区本地持久化、v2 JSON 导出与粘贴 JSON 导入、协议配置、脚本配置、参数化指令与响应映射。
- 原生 JavaScript 协议脚本的基础发送前/接收后执行，以及输入/输出/日志大小限制。
- Linux/BlueZ 与 Web Bluetooth 的基础兼容处理。

当前缺口集中于“高风险能力受控化”：Apple 平台脚本执行已默认禁用；工作区级指令白名单和设备发送策略均已接入真实发送路径，仍需原生 runtime 能力审计；会话记录已支持持久化、筛选和 JSON 导出。

## 设计原则

- 原始 BLE 收发必须始终进入控制台；协议、脚本、映射失败不能隐藏原始数据。
- 标准协议负责可确定描述的封包/解帧；脚本协议只处理无法通过标准结构表达的协议规则。
- 参数化指令只表达业务载荷；帧头、长度、序号、校验、转义和加密属于协议层。
- 所有导入或 AI 生成配置必须先校验和预览；AI 生成配置进入草案，手动工作区导入须经明确确认后才可完整替换当前工作区。
- 脚本、危险命令和真实设备写入必须默认保守，不能因为“配置已存在”而自动信任。
- UI 以连续调试任务为中心：控制台优先，设备树选对象，Inspector 显示当前上下文，配置保持独立工作流。
- 继续拆分 `main.dart`，但不在重构期间改变已验证的 BLE 行为。

## 已完成阶段

### 阶段 1：BLE 基础通信与调试台

状态：已完成基础能力。

- 跨平台 Flutter 工程、主题和国际化。
- 扫描、连接、断开、服务/特征发现。
- Read、Write、Write without response、Notify、Indicate。
- 写入目标和订阅目标选择。
- 通信控制台、HEX/文本输入、时间戳日志和 Mock 服务。
- Linux/BlueZ、Web Bluetooth 的关键兼容处理。

待补：平台真机回归、BLE 服务层异常测试，以及标准协议边界/异常场景的扩展覆盖。

### 阶段 2：工作区、指令与响应映射

状态：已完成第一版。

- `Workspace` 聚合协议、脚本、指令和响应映射。
- `WorkspaceManager` 使用 `shared_preferences` 持久化工作区列表和活动工作区。
- 完整工作区 JSON 导入导出与旧字段兼容读取。
- `CommandDefinition` 支持参数化 HEX 业务载荷、快捷入口与启用状态。
- `ResponseMapping` 支持基于 `CMD/DATA` 的基础字段解析与数据面板展示。

当前边界：导入支持 v1 到 v2 的迁移、完整替换或合并导入，以及冲突时覆盖/保留当前；后续格式升级仍需按同一迁移链扩展。连接默认配置按设备保存，但尚无配置冲突提示；会话日志已完成有界持久化。

### 阶段 3：协议配置与脚本协议入口

状态：标准协议收发已接入；安全加固部分完成。

- `ProtocolDefinition` / `ProtocolSegment` 支持发送与接收片段。
- 支持固定 HEX、载荷、长度、序号、校验、字节序及常见校验算法配置。
- 原生通过 `flutter_js` 执行 `beforeSend(context)` 和 `afterReceive(context)`；发送/接收链路均已接入。
- Web 保留脚本配置，但不执行 JavaScript 脚本。
- 导入工作区会强制禁用脚本并标记 `importedUntrusted`；首次启用需要确认来源和风险。
- 脚本源码、输入/输出帧、日志数量和单条日志长度已有上限。

当前边界：Android/Windows/Linux 的 QuickJS 已有 50ms/16MiB 硬限制，脚本写入有 200ms 限流，改写帧、高风险关键词命令和显式保护命令需确认；iOS/macOS 仅支持编辑脚本，不能执行；工作区级指令白名单限制可复用指令，设备发送策略限制允许特征、最终帧大小和是否允许无响应写入，二者均已接入真实路径；仍缺完整多平台 runtime 能力审计。

## 下一阶段

### 阶段 5：标准协议封包与发送链路

状态：已完成（2026-08-15）。

#### 已落地

- `PacketEncoder` 支持固定 HEX、业务载荷、长度、序号、字节序和 XOR/SUM8/CRC8/CRC16/CRC32。
- 手动发送和参数化指令统一经过业务载荷 -> 标准封包/脚本 -> 最终帧校验 -> BLE 写入。
- 控制台记录业务载荷、最终帧和编码/脚本错误；编码失败不会写入 BLE。
- 无协议时保留原始 HEX/文本发送行为。
- 单测覆盖长度、序号、校验、非法配置和 HEX 解析。

### 阶段 6：接收解帧、校验与响应匹配

状态：已完成基础能力（2026-08-15）；复杂协议和异常恢复仍需扩展测试。

#### 已落地

- `PacketDecoder` 按设备/来源维护独立缓冲，支持拆包、粘包、多帧、帧头同步和长度推断。
- 支持固定字段和校验验证；校验/长度错误会丢弃当前候选并继续寻找后续帧。
- 标准解帧结果进入统一 `CMD/DATA` 映射；脚本模式仍可输出 `cmdHex`/`dataHex`。
- 原始通知始终写入控制台，解码失败不会吞掉原始数据。
- 单测覆盖拆包、多帧、来源隔离和校验错误恢复。

后续补强：帧尾同步、更多长度语义、异常噪声恢复和真实设备长包回归。

### 阶段 7：脚本协议安全整改

优先级：P0，状态：运行时硬边界、确认策略、工作区指令白名单与设备发送策略已完成基础能力；必须在开放第三方/AI 工作区脚本前完成平台审计。

#### 已完成

- 导入脚本一律禁用并标记未信任；首次启用展示来源、风险并要求确认。
- 脚本源码、输入/输出帧、日志数量、单条日志长度和接收任务队列有硬性上限。
- 发送前验证脚本输出的 HEX、非空和最大帧长；原始载荷与最终帧均记录。
- 脚本写入采用 200ms 最小间隔；脚本改写帧、命令名命中重置、擦除、升级、认证等关键词，或命令显式标记为“发送前始终确认”时，发送前必须确认目标特征、载荷和最终帧。
- iOS/macOS 因 JavaScriptCore 无可终止硬超时，仅可编辑脚本；Android/Windows/Linux 才执行带 50ms/16MiB 硬限制的 QuickJS 脚本。
- 工作区可启用“仅允许已选指令发送”，并用指令 ID 持久化白名单；未选中的可复用指令会在载荷编码和 BLE 写入前被拒绝并记录错误，手动控制台原始发送不受影响。
- 已为已知设备持久化发送策略：可限制可用写入特征、最终帧字节上限及是否只允许带响应写入；策略在脚本/标准协议得到最终帧后、BLE 写入前统一校验，覆盖指令和手动控制台发送。

#### 尚未完成

- 当前白名单、设备发送策略、名称关键词和命令级“发送前始终确认”仍不能替代完整设备协议约束；多路通知和主动上报的精确事务归因仍待进一步的协议能力建模。
- Apple 平台若要恢复脚本执行，仍需替换或隔离 JavaScriptCore 执行器，确保脚本可终止。
- 尚无 Android、iOS、Windows、macOS、Linux runtime 能力审计和完整安全测试。

#### 验收标准

- 脚本异常、资源超限或超时不会冻结 UI、丢失原始日志或向设备写入未校验数据。
- 导入 JSON 中即使 `enabled: true`，脚本仍以禁用未信任状态进入工作区。

详见 [脚本执行安全评估与整改计划](脚本执行安全评估与整改计划.md) 和 [脚本运行时平台能力审计](脚本运行时平台能力审计.md)。

### 阶段 8：连接配置、导入边界与会话记录

优先级：P1，状态：已完成首轮能力（2026-08-17）；后续格式升级按既有迁移链扩展。

#### 实现内容

- 已将默认服务 UUID、写入特征、订阅特征与 Web 服务 UUID 纳入设备配置模型。
- 已在连接后自动恢复匹配的写入/订阅选择，并报告不可用配置。
- 工作区 JSON 导出使用 v2 格式并包含活动工作区；导入兼容 v1，并在预览中展示 v1 -> v2 迁移结果，未来版本会被拒绝。
- 导入通过粘贴 JSON 完成，先执行格式校验、工作区预览和 ID 冲突提示；用户可选择完整替换，或合并导入并选择冲突时覆盖当前/保留当前。
- 外部导入即使携带启用脚本，也会强制标记为 `importedUntrusted` 并禁用；复制 JSON 和导入检查/确认均在工具弹窗中提供。
- 已实现有界会话日志：最近 300 条记录在重启后恢复；持久化时单条二进制数据限制为 512 字节、文本限制为 1024 字符，清空控制台会同步清除本地记录。
- 已增加方向、特征、指令与文本/HEX 筛选；支持持久化书签、书签筛选，并可导出当前筛选结果的 JSON；错误可通过方向筛选。
- 已为一次 BLE 发送生成事务 ID，并将 TX、后续 5 秒内首条 RX、脚本日志和映射结果关联后持久化/导出；设备发送策略已可约束写入，但多路通知和设备主动上报的精确事务归因仍需更细的协议/会话能力模型。

当前记录模式已展示有限且可恢复的会话日志，并支持方向、特征、指令、文本/HEX、书签筛选及 JSON 导出；基础事务关联已可在导出记录中追溯。工作区导入支持完整替换或按工作区 ID 合并，冲突时可覆盖或保留当前；未来格式升级和更细粒度字段级合并仍按后续需求扩展。

### 阶段 9：UI 第二轮改造与架构拆分

优先级：P1。

- 控制台改为结构化、可筛选、可定位的通信工作区。
- 发送编辑器展示目标、输入校验、最终帧预览和风险确认。
- 配置使用草稿、保存状态、字段级校验和错误摘要。
- Inspector 按选中日志、特征、命令和映射字段切换上下文。
- 设备树支持筛选与清晰的能力/状态标签。
- 增加键盘快捷键、焦点顺序、语义标签和高对比度验证。
- 继续拆分 `main.dart` 为 app、debug、configuration、records 和 design 边界。

### 阶段 10：AI 协议文档配置助手

优先级：P2，依赖阶段 5-8 的校验与草案基础。

- 先建立带来源证据、置信度、假设、风险等级和审查状态的 `CandidateWorkspace`，不能让模型直接生成可运行 `Workspace`。
- MVP 支持文本/Markdown/TXT 与用户自配 API Key 的 OpenAI-compatible 模型连接。
- 采用“证据提取 -> 候选生成 -> 本地确定性校验 -> 差异审查 -> 用户确认 -> 草案工作区”流程。
- AI 生成的脚本默认未信任且禁用，AI 生成的命令不得自动向真实设备发送。
- MCP 只作为后续外部 Agent、IDE 与团队自动化集成层，不作为首期终端用户方案。

详见 [AI协议文档自动配置方案评估](AI协议文档自动配置方案评估.md)。

### 阶段 11：跨平台回归与发布准备

优先级：P2。

- 为 Android、iOS、Windows、macOS、Linux、Web 建立 BLE 真实设备回归清单。
- 覆盖扫描、连接、重连、特征发现、读写、Web 权限、长包、导入、脚本隔离和会话导出。
- 完善用户文档、示例工作区、协议配置示例和故障排查说明。

## 推荐执行顺序

1. 完成阶段 7 的剩余 P0：Android、iOS、Windows、macOS、Linux runtime 能力审计，并补齐原生目标上的安全回归记录。
2. 完成批量发送保护、日志导出脱敏和更细的设备协议/会话能力建模，作为阶段 7 的后续安全加固。
3. 在阶段 7 的发布前置条件满足并单独确认后，进入阶段 9，推进控制台、发送编辑器、配置草稿、可访问性和 UI 架构拆分。
4. 在校验、草案和安全边界稳定后开始阶段 10 AI 导入助手，最后进行阶段 11 跨平台真实设备回归和发布准备。
