# 脚本运行时平台能力审计

> 审计基线：2026-08-17，代码与依赖静态审计。本文不是 Android、iOS、Windows、macOS、Linux 真机/目标构建回归的替代品。

## 结论

当前应用将可执行 JavaScript 协议脚本限制为 Android、Linux 和 Windows 上的 QuickJS。每次执行都创建独立 Runtime，并配置 50ms 超时和 16MiB 内存上限。iOS、macOS 和 Web 保留脚本配置，但不会执行脚本；因此 Apple 平台 JavaScriptCore 的不可中断执行不会进入协议收发路径。

截至本次审计，脚本能力仍仅适用于本机可信开发人员。平台能力矩阵、依赖安全公告复核和真实目标超时/内存回归尚未完成，不能据此将脚本能力作为共享工作区或正式发布的充分安全条件。

## 依赖与应用边界

| 项目 | 审计结果 |
| --- | --- |
| `flutter_js` | `pubspec.lock` 锁定 `0.8.7`，SHA-256 为 `046428059ac7bef71e305dc35fc24be933b684684a43e83eab7ebd0dc407ad85`。 |
| Runtime 选择 | 插件源码显示 Android、Windows、Linux 使用 QuickJS；iOS/macOS 使用 JavaScriptCore。 |
| 应用创建方式 | `ScriptEngineService` 在 Android/Linux/Windows 直接创建 `QuickJsRuntime2(timeout: 50ms, memoryLimit: 16MiB)`。 |
| Apple 平台 | `isRuntimeAvailable` 为 `false`；发送前脚本拒绝执行，接收后保留原始数据并标记无效。 |
| Web | 条件导入的 stub 不执行 JavaScript。 |
| 主机能力 | 应用仅注入 HEX 上下文和协议计算内建函数；未注册 Dart 消息回调，也未启用插件提供的 XHR/fetch 扩展。静态结论仍需在目标平台验证。 |
| 状态隔离 | 每次调用在 `finally` 中释放 Runtime，不复用用户脚本全局状态。 |

## 已验证项目

- `flutter analyze` 通过。
- `flutter test` 为 54 通过；有限运行时策略的声明测试通过。
- 两条 QuickJS 原生桥接测试在宿主测试环境按条件跳过：有限脚本执行、无限循环中断。它们必须在对应的已构建 Android/Linux/Windows 目标上执行。
- 配置界面与实际执行路径使用同一 `ScriptEngineService.isRuntimeAvailable` 判断，避免 iOS/macOS 将不可执行的 JavaScriptCore 错显示为可用。

## 发布前必须完成

1. 在 Android、Linux、Windows 的构建产物中执行有限脚本、死循环、内存压力、超长输入/输出和高频接收测试，记录引擎版本、结果和崩溃/超时行为。
2. 在 iOS、macOS 中确认脚本编辑可用、启用保持禁用、`beforeSend` 拒绝写入、`afterReceive` 保留原始数据；若未来开放执行，必须先改用可中断执行器。
3. 在全部原生平台验证 JavaScript 全局对象、文件/网络/进程能力和 Dart/Platform Channel 暴露面；未知或无法关闭的宿主能力不得进入正式发布范围。
4. 将 `flutter_js` 版本、哈希、已知安全公告和升级评估纳入发布检查；依赖升级后重跑本矩阵。
5. 对脚本日志和导出实现脱敏默认值，并在启用共享工作区前完成审计留档。
